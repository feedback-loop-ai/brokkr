## Goals

1. `brokkr run --recipe R --enter <gate> [--continues <run>]...` for any recipe, admitted or refused when the recipe and the entry are compiled, before a run id is minted or an event is written.
2. A run entered at `verify` over a finished branch reaches `SHIP-COMPLETE` with no intake, design or first-implement seat, proven on a synthetic recipe and repository.
3. The journal records, typed, the entry and the runs continued; the run view names them, each continued run led by its title, `brokkr_view::title` of its feature, with the whole feature kept in its parts; the gate vouches the branch and names the chain.
4. Nothing skips verification or review that today's tables do not already skip: review stays unavoidable from wherever a run begins, and a work phase is reached in an entered run only by a return.
5. No ordinary run's seat input, manifest, witness or admission moves.

## Non-goals

The proposal's "Left out, and why" stands whole. In addition: no edit to `assert_phase_unavoidable`'s refusal text, no `queued-launch/v2`, no entry on a Looper-bound run, no fetch of a continued run's evidence by the gate, no `default` case added to `recipes/triage`, no edit to any file under `agents/charters/` or `recipes/*/roles/` by this run (D16), no answer to decision 0060's two open items (DD10).

## Decisions

### DD1 — The flag, not the overlay

`brokkr run --enter <phase>`, with `--continues <run>` repeatable, declared on `brokkr run`'s own arguments (D18). The composed overlay was weighed and not chosen, and decision 0094 records why among what it set aside: an overlay's `initial` cannot be told from a recipe's own first phase, so the compiler could not refuse a work-phase entry without a second marker; a recipe is static data and cannot name the runs one re-drive continues; and an adopter would write one overlay per recipe and gate, each restating one word, the copy ruling 5 forbids. The overlay road stays what it is, a recipe's own `initial` (`landing`, `review-first`), and an entry composes over it.

### DD2 — The admission is one function in one new module, run at two moments, and it returns nothing but its refusal

`crates/brokkr-runtime/src/bundle/entry.rs`, a child of `bundle.rs` beside `phases.rs`: `bundle.rs` is over its ceiling, so it gains the one `mod` line and pays for it (DD13). The module holds:

- `pub fn admit(bundle: &Bundle, phase: &str) -> Result<(), EntryError>`: the six facts of the `gate-entry` delta, judged in order, each one private function within ruling 4's ceilings. It runs after the ordinary compile, over the compiled seats (fact 3 reads `Seat.gate`, the compiled whole-gate fact and its witness in one value, D24, D29), and the bundle's own audit from `initial` is untouched: the entry is a second question put to a bundle already admitted, never a rewrite of `initial` before the audit.
- `pub fn admitted(bundle: &Bundle) -> Vec<String>`: the phases `admit` accepts, in `phases` order, the one derivation of the refusal's "the table admits" list and of the table-lint pins (D8; ruling 5).
- `pub enum EntryError` (`thiserror`, ruling 8), one variant per refusal the delta names, each carrying the phase, its witness and the admitted list, its `Display` the operator's text: `Absent`, `Terminal` (fact 1); `Unprintable` (fact 2); `Work { site }` (fact 3, the seat's `WorkSite` printed under its phase as `bounded_site` prints a site, and, for a dialect step the realm does not supply, by its step name and written class as uncompiled); `AvoidsProtected { protected, terminal }` (fact 4); `ForwardWork { work, rule }` (fact 5); `NeedsStrategy { seat, reached_by }`, `NeedsStrategyRuling { group, reached_by }`, `NeedsChange { step, sources, reached_by }` (fact 6, in that rank). `LaunchError` gains `Entry(#[from] EntryError)` and `EngineError` the same, so the launch and the resume refuse with one text.

The two moments: `launch::start` calls `admit` right after `admit_new` compiles the bundle and before the store is opened, so an operator's typo costs no journal; `Cursor::Start` calls it again over the engine's own bundle and its journaled entry, in every process, start and resume alike (DD4). One function, two callers, no second rule (ruling 5). The invariant, that the engine enters only a phase the bundle it runs admits, has the second call as its one home: it is the only place a phase becomes the first `phase/entered`, and the bundle it judges by is `self.bundle`, the one the manifest gate just proved, so no phase can be admitted against one bundle and started under another. `EntryRequest { phase: String, continues: Vec<String> }` is the untrusted input (`NewRun.entry: Option<EntryRequest>`, the ids already canonical, DD7); it never reaches the engine, which takes the `RunEntry` the launch built and checked (DD5, DD7).

Alternatives: a `CompileError` variant (the framing's wording) was not taken because the compile is unchanged and succeeds; the entry is refused after it, by its own enum, and `CompileError`'s text pins do not move. A receipt returned by `admit`, the `AdmittedEntry` with a private constructor that the first visit took, is not kept (the council's renewed visit, both positions): a phase-only receipt binds no bundle, so to mean anything it would have to own or borrow the bundle it admitted and every start would be rewritten around that pair (robustness); and a receipt of any shape is a second guard for one invariant, of which only the `Cursor::Start` judgment is reachable in production, the launch compiling once and handing the same bundle (simplicity, by this section's own argument against a digest receipt). What a receipt would have prevented, a caller handing the engine an entry no admission judged, is fail-closed without it: the start is journaled, and the first drive refuses at `Cursor::Start` by `EngineError::Entry` before any phase is entered; the Proof holds that window with a test, which is also the removal control of the one guard (ruling 9).

### DD3 — The six facts are read off three existing primitives, one roster and one predicate

Nothing in `entry.rs` walks the raw table. Every fact reads `bundle.machine` (typed `Rule`s) and `bundle.seats`:

- **Facts 1 and 2** read `machine.phases`, `machine.terminal`, `is_identifier` and the 64-byte bound. The bound and the grammar are one constant pair in `brokkr_core::policy` beside `is_identifier` (`ENTRY_NAME_MAX`), so the gate test holds one value (D6).
- **Fact 3** is `seats[phase].gate`, a `GateAssessment { AllGate, ContainsWork(WorkSite) }` matched exhaustively (ruling 2): `AllGate` passes, `ContainsWork(site)` is the refusal's witness (D24, D29). The one field replaces `Seat.has_gate: bool`, and `Seat::has_gate(&self) -> bool` is the line the four production reads call (`structural_sites`, `SeatClass::of` for the wrapped verify, `selected_is_gate` at the dispatch door and the engine's gate check). It is set once in `bundle/assemble.rs` where `has_gate` was set: for a sequence seat `parse_sequence` returns it in place of its `whole_gate` bool, `AllGate` until the first step in written step order whose class is work, a dialect step by the class it wrote (`parse_class`) whether or not `step_body` compiled a site for it, any other step by its compiled class, a panel step descending to its first work member in key order; a dialect step with no compiled site is recorded `compiled: false`, so the refusal names it by its step name and written class as uncompiled, never the first compiled work site after it. For every other body `SeatBody::assess(&self) -> GateAssessment` is the one walk, over the cases `is_gate` walked (a single by its class, a panel's members in key order, a selector's cases in key order then its default, a selected sequence's steps in step order, which hold no dialect step: `a_selected_sequence_holds_no_dialect_step`), and `is_gate` becomes a line over it, `matches!(self.assess(), GateAssessment::AllGate)`; `every` is deleted, its at-least-one clause being decided for every body by the compile's minimums (Context), and the comment at `assess` names the three refusal tests that hold those minimums as the invariant's removal control (ruling 9). `WorkSite { path: Vec<String>, compiled: bool }` holds the site's segments under the seat, a case, a step, a member, as the walk descended, and prints under its phase as `bounded_site` prints a label; `WorkSite::seat()` is a single work seat's witness, the empty path, which the hand-built seats of the tests construct too. The predicate and its witness are one value, so no test holds them together (the council, converging).
- **Fact 4** calls one core walk made public: `Machine::reach_avoiding(&self, start, avoid: &[&str]) -> BTreeSet<&str>`, the private `reach` generalised to an avoid set (its one caller `advances` becomes a line over it). The fact holds when `start == protected` or when the set from the entry avoiding the protected phase holds no non-stop terminal. `assert_phase_unavoidable` is rewritten to the same call over `machine.initial`, its refusal text byte for byte as today, so the law has one home (ruling 5) and `bundle.rs` shrinks by the walk it no longer carries (DD13). Decision 0051's constitutional lint is then one function with two seeds.
- **Fact 5** is a breadth-first walk from the entry over the rulings `Direction::of(&machine.phases, &rule.from, next) == Some(Direction::Forward)`, a park (`next: None`) drawing no edge, each phase visited once, rules in table order; the first phase met whose seat fails fact 3 is the witness with the ruling that reached it.
- **Facts 6a and 6b** share one breadth-first walk over every ruling that never enters the strategy phase, `phase_name::TRIAGE`, the runtime's own `pub(crate)` name for it (nothing of the core is made `pub` for this; ruling 6): at each phase met, first the seat's selector (`SeatBody::Select` with `default: None`), then each `(phase, result)` group of that phase that `Machine::unruled_without_strategy(&self) -> Vec<Finding>` reports unruled. That core function is one function beside `sweep`, with no parameter (F2; simplicity's A1): it builds each group as `groups` does, over the rules that carry no condition on the engine-owned `strategy` input, the one `policy/inputs.rs` declares with the `strategy_in` key, read through the private `Condition::name`, and returns `Finding::Unruled` as the sweep does today; the admission keeps the findings whose phase the walk met. `Condition`, `Rule::when` and `STRATEGY_PHASE` stay private; no string vocabulary crosses the crate (ruling 3) and no condition-kind enum is published for one comparison (ruling 6).
- **Fact 6c** is, for each dialect step that `needs_change` (the predicate `engine/sequence.rs` already holds, made `pub(crate)`), in `phases` order and step order: covered by an earlier step of its own sequence when the seat declares `change` (`carry_change`'s rule); else refused when `machine.reach_avoiding(entry, &sources)` contains the step's phase, `sources` being the phases of `CHANGE_SOURCES` listed before the step's phase whose seat declares `change`. `CHANGE_SOURCES` is the roster in `phase_name.rs` that `nearest_change` reads too (D11, ruling 5). The "walk per step" of D17 is this reach with the step's sources removed; no third traversal is written.
- **The rank** (D17): the first failure of the selector fact, else of the group fact, else of the step fact, each with its own walk's first witness; `admit` returns the first `Err` in fact order, so a table that fails two facts names the one listed first.
