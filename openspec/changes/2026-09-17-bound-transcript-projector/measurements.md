## Reading the numbers

- Case A's candidate peak (6,868 KB) sits ~2.2 MB above its own input-only
  control (4,700 KB) and near its parse-only control (6,372 KB): the
  projector itself no longer expands the 262,144 members; the residual is
  the single JSON row and the Rust test runtime.
- Case B's candidate peak (29,764 KB) equals its parse-only control
  (29,104 KB): the residue is the one huge `serde_json::Value`, the
  measured D5 residual, not retained projector events.
- The 10,000 tiny calls retain 7,797 turns charged 3,999,861 bytes and
  truncate, exactly as the structural charge predicts.
- The 10,000 blockless rows retain two turns charged 1,032 bytes and
  never materialize 10,000 empty payload slots.
- Quiet packed rows return zero turns.
- The 50,000-block turn is unchanged: the charge is per turn, not per block.
- Claude and Codex tiny rows pay the same charge and truncate at 7,797.
- The candidate is not an elapsed-time regression on these fixtures: the
  two-parse projection is faster than the base's per-token event
  construction on both packed cases, and the second parse's cost stays
  within 0.06 s wall clock at this size.

## Limitations

Process peak includes the Rust test runtime, file read, JSON parsing and
allocator fragmentation; it is a defensible proxy, not exact allocator
accounting, and no unrelated process maxima are subtracted. It cannot
attribute bytes to individual allocations or detect unresident memory.
The fixture is a fixed moderate source, deliberately not the issue's
multi-gigabyte incident. Elapsed resolution is 0.01 s.

## Independent compiled removals

Each protection was removed alone, compiled, its targeted assertion run,
and the source restored from `target/proof-backup/`. A compile error or an
unrelated refusal is not accepted as proof. Targeted commands are
`cargo test -p brokkr-view --all-features --locked <test>` for the view
cases and `cargo test -p brokkr-cli --all-features --locked --lib <test>`
for the header case.

| Protection | Compiled mutation | Targeted test | Observed failure |
|---|---|---|---|
| Packed coalescing | `flush_run` builds one `String` per member and calls `packed_candidate(piece.len())` per member before concatenating | `packed_coalescing_constructs_one_candidate_not_one_per_token` | `packed_candidates()` left `1000`, right `1`; returned turns stayed `1` |
| Structural charge | `display_cost`: `let mut cost = DISPLAY_EVENT_COST;` -> `let mut cost = 0usize;` | `display_cap_charges_the_constant_and_drops_empty_turns` | `display_cost(&[text("x")])` left `Some(1)`, right `Some(513)` |
| Intermediate retention | `DshCollector::admit` drops the `cost > remaining` check and `remaining -= cost`; `project_dsh` re-applies `display_cap` at the end | `oversized_ordinary_turn_never_exceeds_the_intermediate_budget` | `peak_retained_charged() <= DISPLAY_CAP` failed while `turns.len() == 7_797` still passed |
| Blockless guard | `retain_ordinary_events` pushes every row unconditionally, deleting the `else { blockless_released(); }` arm | `thousands_of_blockless_rows_retain_no_fact_slots` | `blockless_released_count()` left `0`, right `10_000` |
| Codex Count key site | Count site `Rc::clone(id)` -> `Rc::<str>::from(id.as_ref())` | `codex_record_id_is_allocated_once_and_shared_by_its_blocks` | during-pass left `[(Count,false,2),(Count,false,2),(Lookup,true,3)]`, right `[(Count,true,3),(Count,true,4),(Lookup,true,5)]` |
| Codex Lookup key site | Lookup site `Rc::clone(id)` -> `Rc::<str>::from(id.as_ref())` | `codex_record_id_is_allocated_once_and_shared_by_its_blocks` | during-pass left `[(Count,true,3),(Count,true,4),(Lookup,false,4)]`, right `[(Count,true,3),(Count,true,4),(Lookup,true,5)]` |
| Header true EOF | `ui::dsh_header` deletes the `header.len() > DSH_HEADER_CAP` predicate | `dsh_discovery_bounds_the_header_at_true_eof` | `unavailable` left `None`, right `Some(DiscoveryLimit)` for the version-0 cap-plus-one EOF header |

The later mutation of `display_cost` was first written `let mut cost = 0;`
and refused to compile on an ambiguous type; it was corrected to `0usize`
before the run, so the recorded failure is the assertion, not a compile
error. Every mutation was restored and its test re-passed before the next
was applied, and the committed tree is the restored state.
