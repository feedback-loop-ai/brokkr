## What a Codex launch now carries

Every sealed Codex launch is handed the secrets store's path. Its cold
command, the cold replacement of an offered rejoin and the rejoin itself
carry the three measured isolation options. They render the seat's class as
U9c1's permission profile, bound to the seat's workdir and that store:

| Shape | Command, after the binary |
| --- | --- |
| cold and replacement | `exec --json -C <workdir> -c permissions.brokkr={filesystem={…}} -c default_permissions="brokkr"`, the translated effort, the seat's passthrough without its `--sandbox`, `--ignore-user-config --disable apps --disable plugins`, the native plan |
| rejoin | `exec resume --json`, the same profile and selector, the effort, the passthrough, the isolation options, the native plan, `<thread> -` |

The filesystem table is `":root"="read"`, then `"<workdir>"="write"` for
workspace-write only, then `"<store>"="deny"`. One function renders it,
`grammar::rendered` in U9c1's private child `native_controls/grammar/config.rs`,
so the builders and the inline judgment emit and expect the same bytes. No
builder emits `-s`, `--sandbox` or `sandbox_mode` beside a profile. A sealed
Codex launch handed no store is refused at the driver's door, so no sealed
launch keeps the pre-U9c2 `--sandbox` form (below).

How each piece reaches the command:

- **The options** are the isolated configuration the launch's intent builds
  (`mcp::isolated`), appended behind the composed arguments. They are
  recorded as the edge's `built` configuration, exactly as Claude's empty set
  is (U1g2). The final check appends that configuration to its recomposition
  (`Serving::mcp`). So its `carried` comparison requires each option, and its
  rebuild by the same builder reproduces the command. The options are built
  on a shape the standing fence serves as before too, because they only
  narrow what codex loads.
- **One home for their vocabulary (review L1).** The options are one table,
  `ISOLATION` in `grammar/config.rs`, each row an option, its value and the
  `Isolation` it expresses. `grammar::isolation` reads a node against it and
  `grammar::isolation_options` writes the launch's argv from it.
  `adapters/codex.rs` keeps no copy. Test literals stay independent.
- **The profile** is rendered by the builders. `codex_cold` takes the class
  out of the passthrough and leads with the profile (`codex::profiled`).
  `codex_rejoin` re-imposes it where it re-imposed `sandbox_mode`
  (`codex::rejoined`). A class the profile does not render
  (`danger-full-access`, an unknown word) is left as written, and the final
  check refuses it as it always did.
- **The store's path** reaches the final check as `Serving::store`, from the
  same input field the builders read (`secrets_file`), on the rejoin and the
  cold replacement alike.
- **The rejoin's allow-list** (`codex_resume_blocker`) admits the three
  options, read by `grammar::isolation`, so they travel. Any other
  `--disable`, and every `--enable`, still declines the rejoin.

### A run path that is not UTF-8 refuses the seat (run 3, H1; runtime `engine/input.rs`)

Run 2 wrote the store's path into the seat's input with
`to_string_lossy()`. On Linux an operator's `--secrets` override is a raw
`PathBuf`, so a name holding byte 0xff became U+FFFD, which is another
name. The driver's door, the profile's renderer and the final check all
read that one string, and a seat binding no secret never looks the store
up. So the profile denied a file that is not the store and left the real
store readable under `":root"="read"`.

`seat_input` now spells each path a Codex profile is built from with
`spelled`, which is `Path::to_str` and never converts. A path that is not
UTF-8 is refused with the typed `input::Unspelled { which, path }`, where
`which` is the `RunPath` refused:

- **The workdir** is checked first, for a seat whose body runs Codex. The
  check comes before `body_input` writes any spelling of the workdir.
- **The store's path** is spelled wherever it is threaded: to a Codex seat,
  and to any seat that binds a secret. No seat's input carries a renamed
  store.

The refusal reaches the caller as `EngineError::Unspelled`, transparent
over `Unspelled`'s text, and it comes before `EffectRequested` is
journaled. The text, pinned once in the test, is "the secrets store's path
'<path>' is not valid UTF-8, so a seat's input could only name another
path; the seat is refused before it is requested (decision 0065 slice two,
U9c2)", or "the seat's workdir" for the other case. U+FFFD is not looked
for after a conversion, because that cannot tell a real name from a
corrupted one. A seat whose body runs no Codex and binds no secret keeps
its input as before. Its workdir is not refused here, because no profile
is built from it.

**Scope (operator ruling 7 of 2026-10-23).** `EngineError` is declared in
`engine.rs`, so the typed cause is a three-line variant there, beside the
existing `Unreleased(#[from] broker::settlement::Unreleased)`, which it
mirrors. The operator's ruling on U9c2's third run admits exactly that
variant, beside the inline judgment's call line, and nothing else in
`engine.rs`. `git diff --cached crates/brokkr-runtime/src/engine.rs` in run
4 shows those two hunks alone. No other production file outside the row
and ruling 4's two callers moved.

### The driver's Codex door (review H1, M2, M3; `adapters/codex.rs`)

`codex::launch_on_host` is the driver's one Codex entry. It is
`invoke_with_stager`'s Codex arm, and no other production path spawns a
Codex launch. Before `codex_launch_and_cold` runs, and so before the
selector check, the composition, the version probe or any spawn, it asks
`codex::admitted`. That function returns the typed `Unlaunchable`, which has
one variant per cause:

| Variant | When |
| --- | --- |
| `Host(HostConfig::System)`, `Host(HostConfig::Managed)` | the injected observation holds `/etc/codex/config.toml` or `/etc/codex/managed_config.toml` |
| `Storeless` | the input is sealed, its launch record beside its sealed serving inputs, and hands no `secrets_file` |
| `UncarriedRoot` | a store is handed and the workdir is empty or holds a quote, a backslash or a control character |
| `UncarriedStore` | the same of the store's path |

**The launch seam stays typed (second review M2).** `launch_on_host`
returns `Result<_, codex::Unlaunched>`: `Door(Unlaunchable)` for the door's
refusal and `Composition(String)` for `codex_launch_and_cold`'s own,
pre-existing text. The variant becomes text only at the existing outer
boundary, `invoke_with_stager`, through `From<Unlaunched> for String`, which
its `?` applies. The host and store-less tests assert
`Unlaunched::Door(…)` of `launch_on_host`, not a string. The five door
texts and the two seam texts are pinned once, in their own test.

The path predicate is `grammar::carried`. It is the same function U9c1's
profile reader uses for each basic string (`quoted`), so the paths refused
at launch are exactly those the reader could not take back (review M2). The
operator ruled this refusal the row's recorded limitation. No path is ever
escape-encoded.

**What "sealed" means here.** The record and the serving inputs are the pair
the final check (`mcp::served`) treats as a sealed launch. Half that pair is
already refused there in its own words (`UNPAIRED`), and so is the plan
without either (`UNSEALED`). A plan of `null` is refused by the composition
(`NO_AUTHORITY`). Keying `Storeless` on the pair keeps each of those
refusals in its own words, which the existing suites pin
(`the_engines_plan_with_neither_sealed_input_is_refused_at_every_seam`,
`every_model_launch_path_refuses_a_site_with_no_computed_authority`). Every
input that carries any sealed fact is still either handed the store or
refused.

**An unsealed driver run** (no launch record and no serving inputs, a driver
run by hand) is outside H1's scope. Handed no store, it builds no isolation
options and keeps its class as written, `--sandbox` included. Handed a store,
it is launched under the options and the profile like any other.

**The "what would spawn" reader does not refuse (second review L2).**
`codex_command`, the public reader, calls `codex_launch` and not the door,
so it observes no host, requires no store and checks no path a profile
names. Compile's adapter check (`capabilities.rs:1910`, outside this row)
calls it over a sealed input with no run, and so no store. A store refusal
there would refuse every Codex adapter at compile. The reader's doc comment
said it was "composed and refused exactly as a real launch is"; it now says
it reads the composition alone, beneath the driver's door, and why.

### Codex's declared verdicts (adapters/mcp.rs)

`SealedIsolation::admit` reads Codex as it reads Claude and dsh. A measured
assessment admits, `Unsupported` keeps its reason, and `Unmeasured` or a
missing resume entry names its shape. Only a harness with no serving shape
is still missing evidence. The function moved, unchanged but for that arm,

served as before plus the options and the profile, and past it, it is refused
with the declared reason. U1d3 and U0b own those declarations. The MCP
compile fence is untouched.

### The inline judgment (operator ruling 4 of 2026-10-23; review M1)

`judge_inline_codex_launch` and `judge_inline_codex_command` moved from
`grammar.rs` into the new private child `native_controls/grammar/inline.rs`,
re-exported under their old public paths. `judge_inline_codex_launch` (CC 25
at main) is split into `judged`, `engine_option`, `captured` and `counted`,
each at or under 15. In the engine's `local` contribution the profile's
selector counts as the one sandbox fragment, and its definition and each
isolation option are admitted. A profile fault refuses in U9c1's own words,
and a profile of another class refuses. In any other contribution the
options and both tables keep their refusals.

`judge_inline_codex_launch` now takes the run's paths as
`Option<grammar::Bound>`, the type U9c1's reader binds a profile with, made
public with its two fields. Run 1 passed `""` and `None`; that placeholder is
gone. The two callers each pass their own form:

- **Compile** (`bundle.rs`, `admit_inline_launch`) passes `None`: compile has
  no run, so it has no run's paths. Every profile refuses there
  (`Unhanded`). The operator ruled this design in the ruling on run 1; it is
  not an assumption.
- **The dispatch door** (`engine.rs`, `inline_codex_door`) passes
  `Some(Bound { workdir, store })` from the input's `workdir` and
  `secrets_file`.

`judge_inline_codex_command`, called only by the driver's `codex::inline_final`,
keeps its workdir and store and hands the judgment `Some` of them. At compile
and at the door the segments are the sealed record's, whose `local` fragment
is the adapter's `--sandbox <class>`, so an authored profile is refused as
authored. Only the driver's final command carries a profile, and it is judged
with the real paths.
