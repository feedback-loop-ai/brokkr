# U1g2: every launch's isolation sealed at dispatch (part of tasks 8.1 and 8.2)

U1g2 was built in run `0065-slice-two-unit-u1g2-see-the-27a2ab0a` on branch
`s2/U1g2`, cut from main at `2d65ad24`, where U1g1 had landed. This is the
unit's second implement visit. The first returned oversized: it carried the
intent beside the sealed inputs under its own driver-input key and on a new
`SiteSpawn` field, so `capabilities.rs::final_validation`, which builds a
`SiteSpawn` literal and hands each driver a hand-sealed adapter-level launch,
would have had to change as well. Triage ruled the row a chore again with
the same three files. This visit seals the intent inside the typed serving
inputs instead, so it reaches every driver on the path they already travel
and `capabilities.rs` is unchanged.

Only the three production files the row names changed: `engine.rs`,
`native_controls.rs` and `adapters/mcp.rs`. No contract, policy, fixture,
reference, extension or adapter data file moved, and the MCP compile fence
still stands in every build.

## What changed

**The intent is sealed with the serving inputs.** `native_controls.rs` gives
`SealedServing` an `isolation: SealedIsolation` member: the server set
(`empty`, `hands` or exec's `no-model-surface`), the assessment of each
invocation shape (`cold`, `replacement`, `resume`: `measured`,
`{"unsupported": reason}` or `unmeasured`), and the fence the launch was
dispatched under (`standing` or `lifted`). It is written by `value` and read
by `decode_serving` with `deny_unknown_fields`. An absent member is the
inputs' own `'serving.isolation' is missing` refusal, and a malformed one is
`'serving.isolation' is not an MCP isolation intent`. The dispatch door
(`verify_serving`) already admits exactly the inputs the engine sealed, so an
intent that is altered, planted or substituted is refused there, before any
driver starts, with the existing whole reason. The type's `Default` is the
empty set measured on no shape under the standing fence. It serves every
shape as before, and only `capabilities.rs`'s adapter-level plan check builds
one.

**Dispatch writes it from the compile's facts.** `engine.rs`'s
`serving_inputs` seals `isolation_intent(link, facts)`: the set from
`McpIntent::of_candidate` for a selected candidate, or the inline site's
`inline_mcp`; each shape's assessment from the SI2 record (`strict`) beside
that serving's own outcome, found by identity, so a fallback never borrows
its primary's; and the fence from `McpFence::current()`. A shape with no
record, or recorded unmeasured or inapplicable, is unmeasured. An inline site
whose set was never recorded refuses: `dispatch refused: the site's MCP
server set was never recorded, so no isolation intent is sealed beside its
launch (decision 0065 slice two, U1g2)`.

**The serving edge builds and checks from it.** `adapters/mcp.rs` reads the
intent from the sealed inputs alone (`intent`). A driver run by hand, with no
sealed inputs, is served as before. Sealed inputs that cannot be read, an
absent intent among them, refuse with `McpRefusal::Unreadable` before any
provider work. Then, whichever way the fence stands, the intent's server set
must be the one the sealed inputs declare (`sealed_servers`), and an empty
Claude-grammar set must not already carry `--strict-mcp-config` or
`--mcp-config`. Either departure refuses with SI2's tamper cause, `provider
'<provider>' final MCP configuration is not the engine's sealed server set`.
A shape SI2 does not admit (U1g1's verdict) refuses past a lifted fence, and
while the fence stands is served as before: nothing is built, a rejoin is
offered as it was, and dsh keeps the operator's home. An admitted empty set
gains the strict flag and the empty document. `Edge` remembers what was built.
`served` then runs `final_set`, which compares the final command's MCP
options, read by its grammar, with the built configuration and, where the
sealed set holds it, the box's hands server, and refuses with the same SI2
cause. `check_final` takes the built configuration as `Serving::mcp` and
rebuilds it behind the composition, so the spawn consumes the checked argv.

**The settled case: empty set with sealed hands.** The sealed set is `hands`
only where the inputs seal typed hands under a boundary that boxes them
(`namespace`, `seatbelt`, `container`). Under `harness` the harness's own
sandbox carries the hands, and under `open` nothing does, so typed hands
sealed under either intend the empty set. That is `McpIntent::composed`'s own
rule. The empty set is served there, measured or as before, and a `hands`
intent there is not the sealed set and refuses with the tamper cause. The
U1f staging refusal of a sealed empty set is gone.

**Engine composition shrank.** `compose_site` is now a thin wrapper over
`compose_site_at`, which runs `supplied` once with the inline arm folded in.
The duplicated origin filter became `SiteSpawn::extras_of`, and the sealing
chain in `mark_capabilities` is one closure. The test-only `Engine::compose`
and `exec_spawn` moved to `boundary_tests.rs`, their only user. To keep that
file at its baseline, its last-message door test moved unchanged, apart from
its fixtures' paths, to `boundary_tests/door_tests.rs`. `engine.rs` holds its
4,859-line baseline.
`native_controls.rs` absorbed the new types under its 4,320-line baseline at
4,303. Its decoders share one `only` helper for one-member tags, read the
sandbox class through the existing `CLASSES` table and the boundaries through
`SealedBoundary::ALL`, and `named` uses the same table.

## Behaviour that moved

Shipped Claude and LaneTally adapters measure the cold no-hands shape on
Linux. A cold Claude-grammar seat with no hands is therefore now served
`--strict-mcp-config --mcp-config {"mcpServers":{}}` behind its composition.
The replacement and resume shapes are unmeasured, so a work seat offered a
rejoin, and its declined cold replacement, are served as before. On macOS,
and wherever a shape is unmeasured or unsupported, nothing changes until U9b
lifts the fence. `capability_launch.rs` pins this with a host-aware
`ISOLATED` constant.

## Third visit: the review's return

The review of 985cf80a returned four findings, and this visit answers each.

R1 (medium) was that the intent sealed one unnamed resume assessment: the
first `Resume(_)` record. Each record names its own shape, though, and an
adapter may declare several under the same hands. `SealedIsolation::resume`
is now a map from each resume shape's own name to its assessment. Dispatch
writes every `Resume(name)` record under its name, in one pass over the
serving's SI2 record. The serving edge judges a rejoin of `shape` by
`resume[shape]`, and a shape missing from the map is unmeasured. The
intent's reader holds every named reason to the bound. It treats an unnamed
scalar `resume`, or a named entry in an unknown word, as unreadable.

R2 (medium) was that no test showed a changed isolation, well formed, being
refused at the dispatch door. `an_altered_isolation_intent_is_refused_at_the_door`
alters the server set, the cold and replacement assessments, a resume
shape's entry and the fence one at a time. Each alteration gets the door's
whole refusal from `verify_record`, which dispatch runs before any spawn.

R3 (low): `isolation_intent` returns the `thiserror` type
`UnrecordedServers`, whose `Display` is the operator's text, and converts it
only at `serving_inputs`' existing string boundary.

R4 (low): the serving edge's boxed-boundary rule is now one method,
`SealedBoundary::boxes`. It sits beside its consumer in `adapters/mcp.rs`,
because `native_controls.rs` may not grow. The runtime's
`a_sealed_boundary_boxes_exactly_where_core_rules_it` holds it to core's
`Boundary::is_boxed` for every word in `BOUNDARIES`. Protocol reads no core
type, so this copy has to exist, and the test is what keeps it equal to its
source.

R5 stays where the review placed it: a LOW outside this row (see below).
