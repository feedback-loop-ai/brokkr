`s2/U1g1`, cut from main at `81cb15e6`, where U1g0 had landed. This is the
unit's second visit. The first, `0065-slice-two-unit-u1g1-see-the-1e34ce2d`,

the switch on only through a runtime knob, which the 2026-10-07 ruling

proved in the runtime's own tests, and that the CLI switch-on matrix and

[addendum](../operator-ruling-2026-10-03.md) and the amended proof text in

Only the three production files the row names changed. No contract, policy,
fixture, reference or extension file moved, no adapter data moved, and the
realm-wide `mcp` grant refusal is unchanged.

## What changed

`capabilities.rs` stores one typed fence on `Authority`, the
`pub(crate) enum McpFence`, which both `Authority::load` and
`Authority::nothing` take from `McpFence::current()`. Its `Lifted` variant
exists only under `#[cfg(test)]`, so no production path can construct it.
That is the test-only override the ruling asks for, and it is not a runtime
knob. The fence field replaces the private `Loaded` marker. The private
`minimum` field already keeps struct literals outside the module, so the
marker had nothing left to do, and the file stays at its 1,995-line
baseline. `SiteCapabilities` gains a `pub strict` field: beside each outcome,
the serving's SI2 record. `Authority::who` becomes `pub(crate)`, so a strict
refusal opens with the one bounded site prefix.

`bundle/mcp.rs` decides each record in `strictness`. Every model serving is
served cold. A work site, which may be offered a rejoin, is also served as
the cold replacement, and as each resume shape its adapter declares under the
same hands. A gate is never offered a session, so it is judged cold alone.
The hands come from the intended set: `Boxed` where it holds the hands
server, `Harness` where `harness` hands were composed, and `NoHands`
otherwise. The host comes from `target_os`. Each shape's ambient exclusion is
read through the adapter's own `McpSupport::isolation`, and a serving with no
adapter records `Unmeasured(Absent)`. Exec's surface-less set, and a
candidate that composed nothing, record no shape. A fallback is judged on its
own adapter. `resolved` judges each serving right after resolving it. Its
first cause goes through `McpFence::admit`, which returns `Ok` while the
fence stands. Only past a lifted fence does it refuse with
`seat '…' (office '…') in realm '…': <StrictCause>`. The `#[cfg(test)]`
`McpFence::current` reads a thread-local that `McpFence::lift()` sets. Its
`Lift` guard restores the standing fence on drop, including during an unwind.

`agents/mcp.rs`: `McpSupport::isolation` and `carriage` are no longer
`#[cfg(test)]`, because the compile pass is now their consumer.
`McpAxis::strict` maps a record entry to SI2's verdict. `Measured` and exec's
`Inapplicable` yield none. `Unsupported` yields
`StrictCause::Unsupported` with its measured reason. Every `Unmeasured`
cause (legacy, absent or declared) yields `StrictCause::Unmeasured`, naming
the shape by the bare invocation word (`cold`, `replacement` or the resume
shape's name), as a launch names it.

## What the standing fence reports

These are the records U9a's doctor will read. They were observed through the
CLI suites below, on Linux:

| Roster | Work seats (intake, implement) | Review gate | verify, ship |
| --- | --- | --- | --- |
| Claude | cold none measured; replacement none absent | cold none measured | no shape (exec) |
| Codex | cold boxed unsupported; replacement boxed absent | cold boxed unsupported | no shape (exec) |
| dsh | cold none measured; replacement none absent | claude: cold none measured | no shape (exec) |

So once U9b lifts the fence, every work seat of every fresh scaffold refuses
on `replacement`, which U0 never measured, and every Codex seat refuses on
its measured unsupported exclusion. Generated Claude declares only a boxed
resume shape, which a hands-less seat is never judged on, and the generated
dsh declaration names none. On macOS every one of these shapes is absent.

scaffold refuses first at `implement`, not at `intake`. Synthetic shapes are
written for this build's host, so the in-crate expectations hold on Linux and
macOS. The CLI expectations replace `measured` and `unsupported` with
`absent` on macOS.

Moves and fixture swaps: `SiteCapabilities::unjudged`, a test builder in
`fence.rs`, replaces six struct literals. Two are in `capabilities/tests.rs`,
which fell from 2,052 to 2,047 lines. The others are one in
`capabilities/tests/manifest.rs`, two in `engine/capability_tests.rs` and one
in `engine/resume_tests.rs`, which fell from 4,073 to 4,070. In
`mcp_tests.rs`, `inline_review` now builds the inline review compile that
`an_inline_sites_composition_carries_each_serving_input_as_its_adapter_declares_it`
and the new inline test share. No fixture adapter with a legacy or
`unsupported` declaration had to migrate. While the fence stands nothing
refuses on them, and the lifted tests write their own typed declarations.
