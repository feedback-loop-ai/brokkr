## What was built

The protocol gains `Transport::expand_beside(fragment, brokers)`, which
builds `Servers { hands, brokers }` and calls the set's one builder,
`Servers::expand`. `Transport::expand` now calls
`expand_beside(fragment, &[])`, which is the struct it built before, so
hands-only callers are byte-identical by construction; no MCP document
builder exists in brokkr-runtime.

Provisioning returns each slot's inventory `Pin` and its dialect's secret
names; `broker::brokers` seals them, by site label, as `SealedBroker`
(capability, plan locator, plan digest, removals) onto the attempt's
`Selection`. `Engine::mark_serving` seals a site's serving inputs with its
attempt's brokers (`isolation::serving_with`), whose isolation intent is
`SealedServers::Brokered` exactly where the serving's own set brokers
holdings (`marks::brokered_at`, the one projection plans are provisioned
from), and refuses when the brokered capabilities and the provisioned ones
differ in either direction. It then expands the spawn's hands segment
beside the brokers (`isolation::beside`): the sealed fragment's hands-only
expansion must stand in the spawn exactly once, and is replaced by the
whole-set expansion; anything else refuses, nothing is rebuilt around
another. A spawn without brokers keeps every byte. The launch arguments are
written again after the seal, so they name the expanded segment.

The single seat is marked after `provision` and before `execute_panel`/
`execute_sequence`/`run_driver`, as panel members (`member_runs`) and
sequence steps (`single_step`, `dialect_step`) already ordered it; each
passes `selection.brokers(label)` for its own label.

The session question reads nothing from the hands segment: `site_plans`
takes no spawn, and builds each `resume::InstanceKey` from
`argv_for(selection, site, command)`, the selected candidate's argv or the
inline command (engine.rs, `fn site_plans` and `fn argv_for`). The single
seat is still composed before the durable start; only its hands segment is
expanded after provisioning. Plan locators are attempt-specific and enter
neither the instance key nor the requested input:
`a_site_without_a_brokered_holding_provisions_nothing_and_the_requested_digest_holds`
(U7c's, unchanged, passing) holds the requested input's digest equal with
and without a brokered holding, and `a_provisioned_seat_is_served_the_whole_set_its_attempt_wrote`
serves two attempts of one seat each its own plan locator.

McpIntent reading: the row says the intent the engine reads gains the
brokered case. The compile-time `McpIntent` is composed before any holding
is resolved, and its brokered case already exists as
`McpContribution::Brokered` (U7b), which `brokered_at` reads. This run
reads the unit as the engine's sealed intent gaining it:
`isolation::servers` maps `McpIntent::Hands` with provisioned brokers to
`SealedServers::Brokered`. No variant was added to `bundle/mcp.rs`, and the
MCP compile fence is untouched (`McpFence::current()` is still `Standing`
outside tests).

The carried LOW: `marks.rs::brokered_at` carries the comment naming
`bundle::agent_tests::mcp_tests::a_set_without_the_hands_server_or_a_model_channel_carries_no_broker`
as the removal control of the compile-time rejection of an `Unservable`
holding; that test exists and passes. No behaviour changed for it.

One guard was left out under ruling 9: `broker::brokers` reads each pinned
locator with `to_string_lossy`, which is exact because a path that is not
UTF-8 serializes to no record, so `broker::sealed` refuses the attempt as
`Unprovisioned::Write` before `brokers` runs. The comment names the removal
control, `an_attempt_directory_that_is_not_utf8_seals_no_broker`.

## The proof

The new suite compiles a real bundle with the shipped adapters: one boxed
inline Claude work seat (and, for the panel, two inline Claude members),
under `Boundary::Namespace` with no grant, then plants an admitted
`library-docs` holding (server under the fixture root, secret `DOCS_TOKEN`)
in the chosen sites' outcomes, as U7c's fixtures do. Provisioning runs
through `Engine::provision_with` on a protected HOME under `/var/tmp` with

`compose_at` before the durable start, `provision_with`, then
`mark_serving` with `selection.brokers("work")`. The driver's command is
`brokkr_protocol::adapters::claude_command` on the spawn's own argv and the
input the engine sealed. Expected commands and documents are written out
by hand, and each broker's plan digest is read back from the plan file on
disk.

## The carried ETXTBSY fix

`resume_tests.rs::synthetic_dsh` wrote its executables (`node`,
`lib/bin.js`) in place and then ran them. It now writes each one's bytes
to `<root>/sources/<name>` and installs it with
`survey_tests::installed(dir, name, from)`, the existing helper: a child
`/bin/cp` writes `<name>.staged`, and the file is renamed into place. No
fork of the test process ever holds an executed inode open for writing,
which the failing run's "node --version: Text file busy (os error 26)"
needed. `the_real_dsh_driver_journals_no_route_byte_on_the_gated_shapes`
passed in this run's lib suite. No removal can fail deterministically. The
race needs another test thread's `fork` to land between this thread's open
and close of the file, which the test cannot schedule, and the in-place
write passes in any run without that interleaving. So the fix is recorded
without a binding mutation. `resume_tests.rs` holds at 4,069 lines, under
its 4,070 baseline.
