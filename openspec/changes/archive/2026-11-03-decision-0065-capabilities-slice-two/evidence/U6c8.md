## Re-vouch: the terminal tracers

### The cause, and what changed

The controller traced the CI failures, through diagnostic runs #627 and
#632, to the tracer arguments of three tests in
`capability_broker/handoff.rs`. Each ran strace with
`-e trace=/^open -P /dev/tty`. Under `--seccomp-bpf` the kernel's filter
stops every `open` and `openat` of every traced process, and strace
applies `-P` only after that stop. The broker's observer walks the whole
system set with `openat`, hundreds of thousands of entries on a hosted
runner, so each entry became a round trip through the tracer. The
observer then either had no box up within the stage poll's 20 s ("no
stage … reached: []") or overran the fixed 30 s startup deadline, which
is the identity cause. The controller's commit already in this tree,
which allows at most three sealed fixtures at once (`Slot` and
`BOXES = 3` in `capability_broker.rs`), is kept unchanged.

No changed tracer stops an `open` any more:

| Test | Before | Now |
| --- | --- | --- |
| `a_bootstrap_gone_after_the_sender_completed_certifies_nothing` | held ten seconds at the bootstrap's `open` of `/dev/tty`, every `open` of the run stopped | held ten seconds at the bootstrap's `ioctl(TIOCNOTTY)` on `/dev/tty` (`-e trace=ioctl -P /dev/tty -e inject=ioctl:delay_enter=…`), only `ioctl` stopped |
| `a_status_pipe_open_after_the_whole_frame_is_the_handoffs_cause_at_the_deadline` | the same open, forty seconds | the same `ioctl`, forty seconds |
| `a_server_started_from_a_terminal_cannot_open_it` | recorded every `open` of `/dev/tty`: the bootstrap's `O_NOCTTY` open, then the server's `ENXIO` | records `execve`, `ioctl` and `kill` (`EXECS` with its selector widened, plus `-y`): the bootstrap's `TIOCNOTTY`, then its exec of the server, then the server's own account of its open |

The bootstrap makes its `ioctl` only when it holds a controlling
terminal, after the whole frame and its end and before its exec. The two
hold tests therefore now start the broker on a terminal of its own, as
the terminal test does: `Handing::at_a_terminal` wraps the command in
`script(1)` (`on_a_terminal`). That holds under `setsid --wait` too,
since `script` makes a new pty the child's controlling terminal. Without
`/usr/bin/script` it skips with the terminal test's reason, now one
constant, `NO_TERMINAL`. The stage predicate `at_its_terminal` adds a
third condition to "stopped, and still stopped 200 ms later": the
bootstrap must hold `/dev/tty` open. It opens that only to give it up,
so a passing stop at some other call no longer satisfies the predicate.
Every assertion the two tests made before stands unchanged: the exact
cause, one lookup and zero server reads, the box gone, and the 30–32 s
bound on the launcher's end.

The terminal test's server is a purpose-built script, `OPENER`. Its
shell opens `/dev/tty` in a subshell, which keeps its session, and
passes the shell's own error text, or `opened` if the open succeeded, as
an argument of an exec that the tracer records. The test asserts the
following. Exactly one process of the run gives up a terminal. In that
process's trace, from the `TIOCNOTTY` on, the calls are exactly
`ioctl(N</dev/tty>, TIOCNOTTY) = 0`, then the server's exec with its
sealed argv `= 0`, then the server's exec of `/bin/sh -c : tty <cause>`,
whose cause ends in ` /dev/tty: No such device or address`, which is
`strerror(ENXIO)`. Every `kill` the tracer sees is recorded, and each
process's second one is skipped, as `HOLD_SERVER` already does. That
covers the broker's kill of the box's launcher, so the box stands until
the server ends by itself and the teardown cannot race the server's
evidence. On this host the recorded cause was
`/var/tmp/.tmpi4P1Kp/opt/docs/bin/docs-mcp: 2: cannot create /dev/tty: No such device or address`.

## Fourth run: the sender is not waited for

### M1 under the 2026-10-11 ruling

`handed` in `session/readiness.rs` now runs the sender on a detached
thread, not a scoped one. At the startup deadline or on cancellation the
broker sets the sender's given-up flag, ends the box's launcher and returns
the handoff cause at once. It does not join the sender. `ready` then drops
the launched box, which kills and reaps its launcher and closes its pipes,
and `admit` drops the admission, which removes the generated identity's
tree. `serve` exits on that refusal, and the sender ends with it.

The sender borrows nothing that this cleanup releases. `delivered` hands
it its own duplicate of the store's admitted handle and of the control
pipe's writer, and owned copies of the store's path and the declared names.
The only shared state is the given-up flag, which the sender's frame write
polls in place of the attempt's cancellation. The sender's duplicate of the
control pipe closes when its closure returns, before the broker sees it
finished, so a delivered frame is still followed by the pipe's end once
the broker drops its own writer. A sender that answers in time keeps its
own cause, U6c7's typed read causes included.

The third run's partial M1 work is kept as supplied. The store is reopened
`O_NONBLOCK` through its `/proc` handle, so a FIFO or terminal its peer
holds answers at once with its read cause
(`a_store_its_peer_holds_answers_at_once_with_its_read_cause`). L2's
invariant holds in `send_environment`: fewer prepared entries than bindings
refuses with the handoff cause. The reworked readiness tests are kept too.
The third run's held-FIFO unit tests, named in its tables below, no longer
exist. A FIFO no longer holds the sender, so they gave way to that
peer-held test and the two frame-not-taken tests.

## Third run: the security repair

### H1: the descriptor seal fails closed

The bootstrap no longer lists `/proc/self/fd` to mark descriptors
close-on-exec. That listing dropped any entry it could not read or decode
and then approved what was left, so an incomplete listing could let an
inherited descriptor, the status pipe's among them, reach the server. The
seal is now one `close_range(3, ~0, CLOSE_RANGE_CLOEXEC)` over every
descriptor from 3 up. No open descriptor can be missed, and a failed call
refuses with the boxed-exec cause before any exec. Nothing falls back to a
listing.

The CLI crate has no `libc` dependency and its `rustix` offers no
`close_range`, while `Cargo.toml` is outside the row. The seal therefore
lives in the receiver, `secret::exec_confined` in `secret/handoff.rs`,
whose crate already calls `close_range` this way. `entry.rs`'s launch hook
had its own copy of that call; it now calls the receiver's
`close_on_exec_above_stdio`, so the syscall has one home. `secret.rs`
declares `handoff` `pub(crate)` for that, with no change to its line
count. `exec_confined` composes the bootstrap's preparation with the seal
(`sealing`): the seal runs only once the box is prepared, and the exec only
once both held. The bootstrap's preparation is now `detached` alone. Off
Linux the seal refuses, so no server starts. The public signatures are
unchanged.

### M1: the sender is supervised by the startup

Superseded by the fourth run: the sender is no longer joined, and the
store is now reopened without waiting. This section records the third
run's tree.

`delivered` used to call `secret::send_environment` on the broker's own
thread. The store's reopen and read, the binding and the frame all ran
before the first deadline check, after the launch's watcher had ended, so
a held read escaped the deadline and the cancellation and postponed the
box's end. The lookup and the send now run on a scoped thread (`handed` in
`session/readiness.rs`). The broker's thread polls it within the same
absolute startup deadline and cancellation as every other wait. If the
sender has not answered by then, the broker kills the box's launcher at
once and only then joins the sender, so no thread outlives the handoff and
no box outlives the deadline. The answer is the handoff cause. A sender
that answered keeps its own cause, U6c7's typed read causes included.
`send_environment`'s signature is unchanged.

A non-blocking reopen, retried under the deadline, was tried first and
dropped. It would have changed the ruled public signature, and it cannot
bound a read that blocks inside the call, which the tracer's held read
below reproduces.

`crates/brokkr-protocol/src/secret/handoff.rs` (new, 260 lines) is a
consumed private child of `secret.rs`. It holds the sender and the receiver.
`send_environment` reopens the admitted store's path handle through
`/proc/self/fd`, because the observer hands back an `O_PATH` descriptor,
which cannot be read. It then reads that handle with U6c7's typed reader
and binds the declared names with `bind_environment` on a cleared command
that is never run. Last, it serialises that command's environment as one
frame: a four-byte big-endian length, then one JSON object of names to
values, at most 1 MiB and 256 bindings. The frame buffer is reserved whole
and wiped once sent. With no declared name, nothing is looked up. A store
or binding cause is decision 0012's own (`Refusal::Name`, through the
bounded sink). A frame past the bounds is the handoff cause, as is any
transport failure.

`exec_confined` reads the one frame. It refuses a missing or excess length,
a truncated body, any byte after the body (a second or partial frame
included), a name set other than the declared one, a repeated name, a
value that is not a string (so depth is bounded by the closed shape), more
than 256 names, a binding that would replace a fixed name, and a value
with NUL. It builds `NAME=value` entries from the fixed environment and
the bindings, each value a wiped `Secret`. It runs the bootstrap's
preparation and then calls `execve(2)` directly. That call does no `PATH`
search and gives no shell to a file the kernel will not run. The
receiver performs the exec because the raw `execve` is reachable only
through the protocol crate's existing `libc` edge. `Command::exec` would
use glibc's `execvp`, which reruns a script the kernel rejects
through `/bin/sh`. It returns only on failure: the handoff cause before
the exec, the boxed-exec cause after.
