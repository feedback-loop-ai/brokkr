# U6c7: the shared typed store reader (tasks 28.13 and 28.14)

U6c7 was built in run `0065-slice-two-unit-u6c7-see-the-06bcf54f` on branch
`s2/U6c7`, cut from main at `a772af3b`, where U6a had landed. The two
production files the row names are the only production files that changed:
`crates/brokkr-protocol/src/secret.rs` and the new private child
`crates/brokkr-protocol/src/secret/store.rs`, which `secret.rs` registers
with `mod store;` and calls. No contract, policy, fixture, reference,
extension, adapter or bundle file moved. Neither MCP fence was touched, and
no public item was added: the public API listing is unchanged because every
new item is `pub(super)` or private.

## What changed

**One handle, checked and read once.** `store::read_store_file` takes an
open `File` by value, reads the mode from that handle's own metadata,
refuses a mode broader than 0600 through `store::check_mode`, reserves its
buffer from the same metadata with `try_reserve_exact`, reads it to the end,
parses it, and wipes the buffer on every return after the reservation.
A size the allocator refuses is `Io` with the `out of memory` source that
`std::fs::read` gave before the extraction, not an abort. Sizing from the
handle avoids a reallocation only for a store that does not grow after its
metadata is read. The comment says so, and the wipe of a store that grows
mid-read stays best effort, as it was with `std::fs::read`.
The path it is given is used only in causes. `parse_store` holds the
unchanged env format: blank and `#` lines skipped, CRLF tolerated, a split at
the first `=`, a later assignment overriding an earlier one, and values kept
as raw bytes.

**Typed causes, rendered at the old edge.** `store::StoreError` is a
`thiserror` enum with six variants: `Io`, `BroadMode`, `NotAssignment`,
`NonUtf8Name`, `IllFormedName` and `MissingName`. Each `Display` is the
exact text the pre-extraction reader wrote, and each names a path, a line or
a binding name, never a value. `store::bind_names` takes the requested names
out of the parsed entries in request order and refuses a missing one with
`MissingName`. It reads no file and no environment. In `secret.rs`,
`open_store` first checks the mode of the path's own metadata, as the old
reader did before any open, then opens the path and hands the file to the
reader, which checks the handle's mode again. The legacy
`String` surfaces (`read_store` for `store_set`, `store_names` and
`store_remove`, and `resolve_bindings`) call `to_string()` on the typed cause
only at their return. `resolve_bindings` still returns an empty list for an
empty name list before it opens anything, and `store_names` and
`store_remove` still answer an absent store with an empty list and `false`.
`bind_environment` and its single `expose_for_spawn` call stay in
`secret.rs`, and `store_set`'s write path is unchanged.

`secret.rs` went from 706 to 646 lines. `store.rs` has 150 lines and
`secret/tests.rs` went from 508 to 799. All three are within their ceilings,
and `quality/file-lines.txt` records the new counts.

**The review's return (F1–F5).** The first visit opened the path before
any mode check. The review showed two changes in public behaviour from
that: a writerless 0644 FIFO blocked the open instead of refusing on its
mode, and a 0040 owner-unreadable file refused with `Permission denied`
instead of the mode cause. This visit restores the path check before the
open (F1), so those inputs refuse exactly as the pre-extraction reader did.
The descriptor reader keeps its own same-handle check. The second visit
also replaces the infallible `Vec::with_capacity` with the fallible
reservation above (F2), proves at the `resolve_bindings` edge that a miss is
classified without a reread (F3), qualifies the sizing comment (F4), and
writes the gate results below as a table (F5).

## Tests and the mutations that bind them

Nine tests were added to `crates/brokkr-protocol/src/secret/tests.rs`, the
owning suite, with a shared `store_at` builder that writes a store at a given
mode under a canonicalised temporary root, a `fifo_at` builder that makes a
FIFO there with mkfifo(1), and a `within_bound` helper that waits five
seconds for an answer and then releases any open still blocked on the FIFO
with non-blocking opens, so its thread ends. No test moved. The existing tests
in that file pass unchanged. `crates/brokkr-cli/tests/machine_proof.rs` is
untouched: it is over its line ceiling, and its single-accessor walk already
covers production children of the secret module, which mutation M10 shows.

| Test | What it pins |
| --- | --- |
| `store_causes_render_the_legacy_text_at_the_string_edge` | The full text of every cause through the legacy `String` functions: absent store (`... No such file or directory (os error 2)`), broad mode (`permissions 644 are broader than 0600`), line 3 not `NAME=value`, a line 1 non-UTF-8 name, a line 2 ill-formed name, and a missing name, plus the absent store's empty `store_names` list |
| `the_descriptor_reader_returns_typed_causes` | `BroadMode { path, mode: 0o640 }`, then `NotAssignment`, `NonUtf8Name` and `IllFormedName` each at its exact path and line 2, and `Io` of kind `IsADirectory` for a 0700 directory handle |
| `the_descriptor_reader_parses_the_env_format_once_into_raw_values` | Comment, CRLF, blank line, the split at the first `=` and the override give exactly `[("URL", b"later=c"), ("RAW", b"\xff\xfe")]`. The raw value then refuses at injection as `BindError::NotUtf8("RAW")` |
| `the_descriptor_reader_checks_and_reads_the_handle_not_the_path` | After the path is renamed over by a 0644 store, the handle that was opened first still reads `["ADMITTED"]` with value `first-value` |
