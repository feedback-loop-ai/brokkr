## Review return R1: the sentence promised an exclusion not yet enforced

The review of 9ccdde2c sustained one medium security residual. The shared
`AMBIENT_MCP` sentence said a seat's MCP servers are "never inherited from
your own MCP configuration", and quickstart.md and starters/rust.md repeated
that assurance. It is false until U1g's strict admission lands, because
nothing yet writes `mcp_isolation` into a launch and an unboxed claude or
codex seat still starts the operator's servers (docs/security-model.md, "What
Brokkr does not enforce"). The sentence now states the ruling and that it is
not enforced, without promising inheritance:

```text
Decision 0065 rules that a seat never inherits your own MCP configuration, but this build does not enforce it yet: a seat may still start the MCP servers your harness configuration names.
```

init.rs's constant, init_doctor's pin and the six guide transcripts carry it.
The quickstart.md and starters/rust.md prose now say decision 0065 makes a
seat's MCP servers the engine's to compose but that this is not enforced yet,
and that a seat may still start the servers in the operator's own harness
configuration. A longer draft that also named each adapter's `mcp` record
raised `quality/ratchet.sh clones` to five data findings, adding
quickstart.md:198 with bun.md:41. The shorter sentence brought it back to the
same four re-keyed findings as before (quickstart:198/python:31 at 16 lines,
