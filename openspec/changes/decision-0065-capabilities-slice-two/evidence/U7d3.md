## The design as built

The protocol parser reads an object of exactly `names` and a non-empty
`measured`, refusing an array outright because serde would otherwise read an
array into the struct by position. Each name holds decision 0012's grammar
(`secret::valid_name`) and none is written twice. The measurement is evidence
the adapter digest pins; nothing reads it.

The loader admits `harness_auth` as a top-level key and stores on `Adapter`
the sorted, deduplicated union of the declared names and every `credentials`
value. An absent declaration therefore reads as the credentials alone, which
keeps every `brokkr init` scaffold and every adapter written before MB4
loading.

dsh's names come from `credentials`, and its declaration lists none. The
recorded measurement (below) shows dsh authenticates each route with the
variable its provider row's `apiKeyEnv` names, and those are exactly the
four `credentials` values. Declaring them again would write one fact twice
(decision 0071 ruling 5), and taking them from `credentials` means a route
added later is judged without a second edit.

`Serving::auth` carries the serving adapter's names: the assessment takes
them from its adapter, each bundle candidate from its own provider's adapter
(so a fallback never borrows its primary's), and an inline site carries none,
as the operator ruled. `Authority::holding` calls `Holding::collision` right
after `sealed`, before the fence's own words, so a collision reaches GP1's
required and wanted forms through `Unserved` and `Cause::incompatible`.
`Authority::sealed` is unchanged and independent of the candidate. A native
holding binds no secret and never collides.

### Open LOWs for the operator

The cloud SDK credential-chain variables are not declared for claude or
lanetally: `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`,
`GOOGLE_APPLICATION_CREDENTIALS` and `AZURE_*`. The provider SDKs' chains
read them, not Claude Code's own credential list, so this follows the
controller's instruction. A dialect binding one of them is therefore not
refused as a collision. Whether to declare them is the operator's ruling.

The scaffolds in `crates/brokkr-cli/src/init/adapters.rs` write no
`harness_auth` declaration. A folder initialised by `brokkr init` therefore
judges collisions by its credentials alone. That file is outside U7d3's row,
so it is a follow-up.
