## What was built

`OperatorCommand` (brokkr-core `fold.rs`) gains `Release`, the word
`release`. `acceptance_refusal` refuses it only after a terminal, as it
does every command, and an accepted release folds to nothing: the run and
its attempts stand where they were, the pending command disposed of. The
CLI reaches it unchanged through `verbs/delivery.rs`, which parses the
word with `OperatorCommand::parse` and calls `operator_command`.

`operator_command` (runtime `engine/operator.rs`) hands `Release` to its
new private child `operator/release.rs`; `retry` and `stop` keep their
path. The Looper bridge refuses `release` as `command_not_allowed`
(`fenced_refusal` matches `Known(Retry | Stop)` only), so the operator's
console is the one door to the exception.

`release.rs` opens the coordination root the host observes, as dispatch
does (`broker::observed`), and calls `settlement::attested`. Under the
existing admission lock (`root::locked`) that function reads the protected
inventory with the existing reader (`inventory::inventory`), keeps every
reservation of the run whose journal is the operator's store (`beside`,
now `pub(super)` in admission.rs, the one home of that canonicalisation)
and that holds an attempt standing, each read whole, and judges each
standing attempt against the run's journal. Then, still under the lock, it
calls back into `release.rs`, which journals the command fenced on the head
the release was judged on: `operator/commanded` with `command: "release"`,
`args: {"reason": …}` and the operator, and on a live run the
`operator/accepted` that disposes of it, fenced on the command. A run
already completed or stopped takes no acceptance (`fold` refuses one
there), so there the command is the whole record, as `supersede`'s is.
Only after that does `attested` seal each attempt's cleanup `Settled` and
settle it with the existing `admission::settled`, sealing the reservation
with the existing `admission::sealed`. Nothing is folded, replayed or
journaled of the attempt.

Refusals are `settlement::Refused`, carried as a new private
`Cause::Refused` of the existing `Unreleased` (so `EngineError` gains no
variant and the public API no item): `Unreserved(run)` where no attempt of
the run stands, `Recoverable(attempt)` where its every driver's record is
sealed Settled (U8e2's own `recorded_settled`), `Running(attempt)` where
the journal shows no terminal event for it (settlement's own `ending`),
and `Moved` where a peer moved the journal beneath either fenced append.
The first three are decided before anything is written; a lost fence on
the command writes nothing, and one on the acceptance disposes of the
command with `operator/rejected` `lost_fence`. Every refusal leaves the
reservation standing. A host with no protected coordination root refuses
with MB3's `Unknown::Root`. settlement.rs's module doc names the exception
and that nothing else may use it; the CLI's `<COMMAND>` help says what the
operator attests.

## Notes for review

An attempt that ended with every driver sealed Settled but was never
recovered, as `operator conclude` leaves one (U8e2's
`operator_conclude_folds_nothing_of_a_recoverable_attempt`), is refused
as ruled, though no restart will now recover it: its reservation then
stands until an operator ruling says otherwise. Since visit two it is
refused `Settled`, whose words say exactly that, rather than
`Recoverable`'s "resume the run instead".

`release` takes every attempt of the run standing at once, all or nothing:
a run with one ended attempt and one still running is refused `Running`
for the latter.

LOWs outside this row, not fixed: `verbs/delivery.rs` prints `recorded
operator release; continue with: brokkr resume --run <run>`, which is
wrong for a stopped run, and its unknown-word refusal lists `'retry',
'stop', 'supersede' or 'acknowledge'` without `release`; `lib.rs`'s
`Operator` doc, rendered as the verb's summary, says `(retry | stop |
supersede)`. The `release` args shape, `{"reason": …}`, has no payload
schema under `contracts/` as `supersede`'s has.

## Visit two: the review's return

The review of a758a787 returned residual/medium with four author findings
this visit answers, all inside the row or its private children.

M1, release only an indeterminate end. `judged` (now in the new child
`settlement/attestation.rs`) matches each standing attempt on two facts,
whether its every driver is sealed Settled and how the journal ended it,
exhaustively: in flight and all Settled is `Recoverable`; ended and all
Settled is the new `Settled`; in flight otherwise is `Running`; ended a
success or a failure is the new `Certified`; only an `EffectIndeterminate`
end is released. `Certified` reads "attempt '<attempt>' ended a success
or a failure, not indeterminate; release only an attempt that ended
indeterminate".

L2, state-aware wording. "Resume the run instead" is now said only of an
attempt still in flight, the one U8e2's restart recovers. An ended attempt
whose drivers are all Settled is refused `Settled`: "every driver of
attempt '<attempt>' is sealed Settled, so it is not the operator's to
release, and it has ended, so resuming the run does not recover it: its
reservation stands". The refusal stays as ruled; the dead end is named, not
lifted. The second half of L2, `verbs/delivery.rs`'s success line telling
every release to resume, is outside the row and still carried.

L1, a stop's conclusion cites the stop. `operator_stop_reason` selects the
latest `operator/accepted` whose command (read from the `operator/commanded`

cause. The unrecorded fallback test in `engine/tests.rs` passes unchanged.
