## What changed

`capability_calls.rs` stays the one home of the observation type and its
encoding. `legacy_tool(self)` becomes `shown_tool(&self)`, with the same
table: the `tool` a row has always shown, clamped to 80 characters. The
new `Observation::onto(self, row)` writes that shown `tool` where there is
one, and the observation itself, whole and unclamped, under
`OBSERVATION_KEY`. Both are `pub(super)`; no public API moved.

`adapters.rs` switches its three existing emission sites to `onto`:

- Claude (and LaneTally, which speaks Claude's stream) on each `tool_use`
  block;
- Codex on each `item.started` and `item.completed`;
- dsh on each `tool/call`.

dsh still writes no row before its first turn or for a call that names
no tool, as before. Every row that carries a call now also carries its
observation. The file went from 7,209 to 7,202 lines.

Every path that takes a driver's checkpoints to the store goes through
`Calls::consume` before `Checkpoints::offer`. That is the single-site
sink at `engine.rs:2097` and the panel sink at `engine.rs:2413`.
`oneshot::run_once` (Muninn) journals nothing and reads only usage.
So the engine alone writes the public group, and a private observation
that reached the store would be refused by v6, as M2 below shows.

A held call with no harness id now takes CC2's exact cause. So does an
empty id. Neither is downgraded to an ordinary row. An observation with
no tool, or with an empty one, claims nothing and stays an ordinary row,
as U4e ruled.

## Assumptions read from the framing

"Switch from legacy lowering to normalized observation output" is read as
adding the observation beside the row's existing `tool`, not replacing
it. The engine treats `tool` as legacy telemetry, outside the attribution
group (`checkpoints.rs` ATTRIBUTION). `Stamp::apply` overwrites it with
the unclamped name on an attributed call. U4e and U4f injected their
fixture observations in exactly this shape. Dropping `tool` would have
erased the shown tool of every ordinary row. M6 shows that dropping it
also makes v6 refuse the Claude rows that carry a `target`.

All three formats emit. The engine's consumer already matches
`Format::Dsh` exhaustively and judges its ids fresh (U4f). dsh holds no
native capability in any shipped dialect, so its observations attribute
nothing today. They do let a future dsh holding take CC2's refusal rather
than pass unseen.
