## What moved, and how it was split

`mod capabilities;` (`crates/brokkr-cli/src/doctor/capabilities.rs`) and
calls `capabilities::report_capabilities` where it called
`report_capabilities`. The one contiguous block that ran from `scope_words`
through `report_grant` (doctor.rs lines 759–1174 on cb89e119) moved whole:
`scope_words`, `disposition_words`, `report_native_assessments`,

`bounded_line`, and `restriction_names`, `Authority`, `Disposition`,
`NativeInventory`, `Outcome`, `Requests`, `Strength` and `ADAPTER_SEAT`
from `brokkr_runtime::capabilities`. The realm, house and dialect reporting
stays in doctor.rs, and so does `safe`, which the child reaches as
`super::safe`. `report_capabilities` and `report_grant` are `pub(super)`:
the first for `doctor()`, the second for the existing
`a_grant_line_reads_its_binding_by_kind_and_assumes_no_native_provider`
test. Nothing else widened. `doctor` is a private module of the crate, so
no item of it is public API, and `git diff --stat HEAD -- quality/public-api`
printed nothing.

split along its own phases, and its doc comment stays on it:

## The binding enum (U2's carried LOW)

The read map was `BTreeMap<&str, Option<(String, String)>>`, consumed
through `bound == Some(&None)` and `bound == Some(&ours)`. It is now
`BTreeMap<&str, Binding>`, where `Binding` is a private enum with three
states. `Unread` means the realm declares no grant of the capability.
`Failed` means its grant did not validate. `Native { grant, provider, key }`
means its grant binds that provider's adapter key. `report_native` matches
it exhaustively, with no wildcard. A `Native` whose provider and key are
this harness's prints the granted line. `Failed` prints UNKNOWN. `Unread`,
and a `Native` bound to another provider, print NOT granted, as
`(None, false)` did before. `report_grant` still returns
`Option<(String, String)>`, so the existing test of it is unchanged.
`report_realm` turns its answer into `Native` or `Failed` at the insert.
