# U6c2: the consumed broker session extracted (tasks 28.3–28.4)

Run `0065-slice-two-unit-u6c2-see-the-a60fec0c` built U6c2 on branch
`s2/U6c2` from main at `320de6c9`, where U6c is installed. The unit
changed exactly the row's two production files,
`crates/brokkr-cli/src/broker.rs` and the new
`crates/brokkr-cli/src/broker/session.rs`. No protocol, runtime, store,
view, contract, fixture, policy table, reference schema or extension file
moved, and no MCP grant was touched: the U9 fence stands.

## What changed

`broker.rs` keeps the command line's parsing (`BrokerError`,
`plan_locator`, `plan_digest` and `PLAN_LOCATOR_MAX`) and the `run`
handler. It registers `mod session;` and its `Serve` arm calls
`session::admit(&plan, &plan_digest)?` immediately, before it returns
SD3's `Refusal::ServingIncomplete`. The file went from 492 to 92 lines.

`session.rs` (414 lines) holds U6c's binding and admission, moved
verbatim. That is the protected-root walk, the inventory pin, the digest,
the closed parse and the owner check in `bound`, then MB3's refusal order
in what was `admit` and is now the private `checked`, with every helper
and constant they use. Its one `pub(super)` item is
`admit(locator, digest) -> Result<(), Refusal>`, which runs `bound` then
`checked`. The `Layout` and the parsed `Plan` never leave the module; only
the shared `brokkr_protocol::broker` types cross it. A `diff` of the
original file against the two new files, concatenated, showed no change
to any moved function body beyond the two named here.

The first of the two U6c lows carried here is closed. `one_line`, a
second copy of the line sink that lacked its bound, is gone. An invalid
binding name now refuses with
`Refusal::Name(bounded_line(&cause))`, through
`brokkr_protocol::native_controls::bounded_line`. That keeps decision
0012's cause and the control-character escaping, and cuts the escaped
cause to the shared 512-scalar `LINE`, its last scalar `…`. The existing
newline-injection assertion in
`binding_names_are_checked_then_fixed_keys_refuse_before_lookup` passes
unchanged.

## Tests

The owning suite is `crates/brokkr-cli/tests/capability_broker.rs`
(1,076 to 1,089 lines). Its twenty existing tests are byte-for-byte
unchanged and pass. One test is new:
`a_long_binding_name_is_cut_to_one_bounded_line` seals a plan whose one
binding name is a newline followed by 600 `é`. The refusal's cause must
be `secret name '\n` followed by 496 `é` and `…`, exactly 512 scalars
(asserted by `chars().count()`, while the cause is longer in bytes). The
emitted stderr must be that cause between the CLI's own `error: ` prefix
and its newline, with exit code 1. No test moved and no other test file
changed.

`cargo test -p brokkr-cli --test it capability_broker::` ran 21 passed,
0 failed.

`crates/brokkr-protocol/src/broker.rs` unmodified. The suite then ran 21
passed. Nothing in that file moved in this unit; the positional-array
low there stays U6d's.
