## What the unit builds

`hands/namespace.rs` (173 → 612 lines at the third visit) now owns both
box profiles.

The builder opens a closed `Profile`, either `Workspace` or `Server`.
`Profile::system` projects the one `HOST_TOOLCHAIN_BINDS` table, and only
the server replaces `/etc/ssl` with `/etc/ssl/certs`. That projection is
the server's whole system set, and nothing else lists system paths. The
workspace keeps `--new-session`. The server opens without one, so it stays
in the broker's process group (MB5). Both keep die-with-parent, the
PID/IPC/UTS unshares, the cgroup unshare where supported and the
capability drop.

Identity generation is split in two. `generated` produces the four files'
text, `generate` writes them, and `generated_in` binds them. The resolver is
a closed `Resolver`: `Files` writes `hosts: files`, and `Dns` writes
`hosts: files dns` and binds the host's `/etc/resolv.conf` read-only. That
file is the only one of the host's `/etc` the box ever binds. The
workspace still calls `identity(etc)`, which keeps its files-only resolver.

The `Namespace` keeps every bind's host source and box destination as it
serializes them. The paths the profile checks are therefore the paths it
mounts.

The server program is resolved by `ServerProgram::resolve(launch, home)`.
An absolute launch name is used as written, and a bare name is looked up
on the fixed `SERVER_PATH` (`/usr/local/bin:/usr/bin:/bin`). A relative
name holding a `/` names nothing, and the cwd and an ambient PATH are
never read. The name must be an executable regular file, with symlinks
followed. It is then canonicalized, and `layout` applies MB3's closed
distinction to that canonical path. A file directly in a canonical system
bin is `Tree::System`. Any other file's root is its parent, or the
parent's parent when the parent is a `bin` or `sbin`. A root that is `/`,
the trusted HOME or an ancestor of HOME refuses with `ProgramTree`.
`SYSTEM_BINS` moved here from `session.rs`, which keeps it in one place.

`ServerBox::prepare(program, profile)` builds the whole non-secret intent.
`ServerProfile` carries the seat's sealed `Reach`, the projected `Network`,
the bootstrap and the arguments. The mounts go in this order (as amended by
the review return below):

1. The skeleton and the projected system set.
2. The canonical alias of each system source linked outside the set, bound
   from the same source (`/sbin` at `/usr/sbin` on a merged-`/usr` host).
3. Distinct private tmpfs mounts on `/runtime/home` and `/tmp`.
4. The program tree, read-only at its canonical path. A package root is
   added only when no system source already holds the root, so a package
   contained in the system set keeps its own tree identity and gains no
   mount. A root that is or holds any path the box already set up, or
   lies inside `/etc/ssl` outside its certificates, refuses `ProgramTree`.
   A system entry is its one file. It is bound alone, never its
   directory, where no system source holds it (`/usr/sbin` on a
   split-`/usr` host; third visit).
5. The bootstrap, as one read-only file.
6. The resolver bind on the shared network.
7. The generated identity binds.

The private tmpfs mounts come before the package and the bootstrap, so a
source under `/tmp` is mounted on top of the private `/tmp` and stays
visible.

`clear` then checks the seat's reach before anything is created. Each path
is compared both as spelled and as it canonically resolves. It refuses
`LaunchInReach` first, when the launch name's own file or the executable
lies in a writable root. It then refuses `BindOverlapsReach` when any
mounted source or destination (the identity's four `/etc` places included)
lies within a reach root or holds one, or when a reach root holds the
temporary directory the private session tree will be made in.

Only after reach is cleared does `prepare` create that tree, write the
generated identity into it, bind it, and set MB4's fixed environment. That environment is the seven entries of
`SERVER_ENVIRONMENT` after the `BROKKR_HANDS_BOX=1` that every box sets.
The box enters `/runtime/home` and runs the canonical executable with its
arguments. `server_environment()` reads its eight names from that same
table, so the entries the builder sets and the names a binding may not
take are one fact. The box holds its private session tree, created as
`brokkr-hands-server-…` under the broker's temporary directory, and
removes it on drop. The identity files are generated into that tree.

`hands.rs` stays at exactly 1,170 lines. Its `pub use` line now also
exports `server_environment`, `ServerBox`, `ServerProfile` and
`ServerProgram`, and `box_argv` opens `Profile::Workspace`. The
`HOST_TOOLCHAIN_BINDS` doc comment was reworded within the same lines to
name the server projection.

`broker/session.rs` (414 → 377 lines) consumes the profile in MB3's order:

1. `well_formed` requires the plan's fixed environment names to equal
   `hands::server_environment()`, in order. This replaces its separate set
   and name-grammar checks.
2. Binding names are validated, then any name in the builder's reserved
   set refuses `StartupInputs`.
3. `ServerProgram::resolve` resolves the program, and `sealed` requires the
   plan to have sealed that very canonical executable and the same `Tree`.
   A mismatch refuses `ProgramTree`.
4. `ServerBox::prepare` runs with the plan's reach, network, bootstrap and
   `argv[1..]`.
5. The control-root identity check and the store-in-box check now run
   against `server.paths()`, every path the box mounts. They no longer
   compare only the tree and the bootstrap.

The old `tree`, `reach` and `binds` functions are removed. An admissible
plan still ends in `broker serving protections are incomplete` before any
lookup or start. The unit claims neither complete source identity nor
readiness: U6c5 owns observation and U6c6 owns the bootstrap.

## Readings and knowingly bent principles

- **A scratch failure takes the identity cause.** When the private scratch
  cannot be created or written, the refusal is
  `MCP server box filesystem identity is not protected`. MB3's own cause
  for a failed private directory, `MCP server box could not be
  established`, has no `Refusal` variant yet, and `broker.rs` is outside
  this row. It fails closed. This is a LOW for whichever unit adds the
  establishment variant (U6c6). It is not a blocker.
- **The fresh tmpfs mounts are not reach-checked.** Every bind's source
  and destination is compared with reach. The tmpfs destinations
  `/runtime/home` and `/tmp` are not, because they are fresh and empty and
  expose no host path. Comparing them would refuse every seat whose
  workspace lies under `/tmp`.
- **The plan has two reach lists.** The plan's `Reach` holds `writable`
  and `readable`, so a hands `overlay` bind is checked as a readable root,
  `rw`, workspace and Git as writable, and `ro` as readable.
- **The argv has no production reader yet.** The command closing the argv
  is the canonical executable and its arguments, until U6c6's bootstrap
  wraps it. Since the review return, `ServerBox` holds the finished
  `Namespace` itself, and `argv()` is a `#[cfg(test)] pub(super)` reader,
  so nothing public exists without a consumer (ruling 6). The launch unit
  (U6f) gives it its production reader.
- **A wrong environment list is a shape refusal.** A plan whose fixed
  environment names differ from the builder's, including in order, is
  refused as unbound, not as a startup-input collision.
