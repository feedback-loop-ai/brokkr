# v0.12.0 “Gleipnir”: capabilities the realm grants, a fleet you read at a glance, and gates that hold the code's shape

Gleipnir is the binding the dwarves made: thin as a ribbon, and nothing
breaks it. In this release a seat holds only the powers its realm grants. It
also brings a terminal console that shows who must act and what each run is
doing, and a set of gates that hold the code to its architecture. It includes
the changes merged since
[v0.11.0](https://github.com/feedback-loop-ai/brokkr/releases/tag/v0.11.0).

**This release breaks recipes that write capability flags into a driver
command.** Read [Upgrade and compatibility](#upgrade-and-compatibility)
before you install it over a working setup.

## What changed

- **Capabilities are the realm's to grant (decision 0065, slice one).**
  - **Typed tools.** A seat declares its tools as data (`tools.allow`,
    `tools.deny`, `tools.sandbox`), and the engine lowers them to each
    harness's own flags. Every capability is off until the realm's map
    (`realms.v6`) grants it.
  - **Native powers.** A harness power with no measured way to turn it off
    refuses the seat; it is never silently on.
  - **The final launch check.** It re-reads the exact command handed to a
    harness.
  - **Bound to the bundle.** Charters and policy are read once and bound to
    the bundle's identity.
  - **Recorded and reported.** The run manifest (`run-manifest.v11`) records
    the realm, its grants and each seat's controls. Every prompt states what
    the seat holds, and `brokkr doctor` assesses the whole plan through the
    launch's own final validation.

  [#319](https://github.com/feedback-loop-ai/brokkr/pull/319),
  [#507](https://github.com/feedback-loop-ai/brokkr/pull/507)
- **A fleet you read at a glance.** `brokkr tui` lists runs by who must act:
  needs you, then running, recent and older.
  - **Each row** carries a title, the ruling and its highest residual. A run
    that folds to running but has been silent past every shipped deadline
    shows as **stale**, and a quarantined run says what it needs.
  - **On a wide terminal,** the fleet opens on the first run that needs you,
    in three columns:
    1. the runs;
    2. a run dashboard (`d`), which draws the run's live graph;
    3. a live or findings column (`f`), with the running seat's latest events
       or the last review's findings.
  - **Keys.** `c` expands a commission. A running row opens in place with →,
    `l` or Space, and folds with ← or `h`.

  [#502](https://github.com/feedback-loop-ai/brokkr/pull/502),
  [#509](https://github.com/feedback-loop-ai/brokkr/pull/509),
  [#510](https://github.com/feedback-loop-ai/brokkr/pull/510),
  [#489](https://github.com/feedback-loop-ai/brokkr/pull/489)
- **One run, one view.** On a terminal, `brokkr run`, `brokkr resume` and
  `brokkr watch --run <id>` open the same run view as `brokkr tui` and
  Enter: graph, seats and trail, live.
  - `q` closes the view and the run keeps driving.
  - Ctrl+C stops the run as SIGINT always has.
  - Off a terminal, every verb prints exactly what it printed before.
    `--no-view` keeps the old output on a terminal too.

  [#510](https://github.com/feedback-loop-ai/brokkr/pull/510)
- **A timed-out attempt ends its whole process tree.** This covers detached
  descendants, the harness and its tools, before the report returns, so a
  retry can no longer overlap a seat that is still writing. An end that
  cannot be proven is `indeterminate`.
  [#483](https://github.com/feedback-loop-ai/brokkr/pull/483)
- **Journal and engine.**
  - **Contention.** A peer's journal lock delays a working seat's
    checkpoints and never ends its attempt.
    [#466](https://github.com/feedback-loop-ai/brokkr/pull/466)
  - **Locked session trees.** A hands session tree is locked for its owner's
    life, and a dead owner's tree is reaped at the next start.
    [#469](https://github.com/feedback-loop-ai/brokkr/pull/469)
  - **The hot path.** Appends and engine turns pay only for what changed.
    [#458](https://github.com/feedback-loop-ai/brokkr/pull/458),
    [#459](https://github.com/feedback-loop-ai/brokkr/pull/459)
  - **One admission.** Run, resume and rerun admit through one runtime use
    case. [#495](https://github.com/feedback-loop-ai/brokkr/pull/495)
- **Operator surfaces.**
  - **The CLI reference** is rendered from the parser itself, every
    documented command parses, and every exit code comes from one enum.
    [#490](https://github.com/feedback-loop-ai/brokkr/pull/490)
  - **Operator commands** are one typed verb with typed refusals and one
    fence, and the views offer only the commands the fold would accept.
    [#446](https://github.com/feedback-loop-ai/brokkr/pull/446),
    [#456](https://github.com/feedback-loop-ai/brokkr/pull/456)
  - **Spend.** Every surface reports every attempt's spend.
    [#391](https://github.com/feedback-loop-ai/brokkr/pull/391)
  - **Journals.** Reading verbs open the journal read-only, and every journal
    verb opens the map's journal.
    [#384](https://github.com/feedback-loop-ai/brokkr/pull/384),
    [#389](https://github.com/feedback-loop-ai/brokkr/pull/389)
  - **Quarantine.** A corrupt run is quarantined on every surface instead of
    taking the fleet down.
    [#386](https://github.com/feedback-loop-ai/brokkr/pull/386)
  - **Masking.** A bound secret's value is masked wherever a transcript is
    read. [#390](https://github.com/feedback-loop-ai/brokkr/pull/390)
- **Seats and secrets.**
  - Secret bindings reach every harness, and a bridge transport outside the
    sealed audience is refused.
    [#381](https://github.com/feedback-loop-ai/brokkr/pull/381)
  - A model seat whose charter cannot be read refuses to start.
    [#387](https://github.com/feedback-loop-ai/brokkr/pull/387)
  - `brokkr init` scaffolds the agent CLI found on PATH, a boundary that
    works on the host, and a read-only reviewer.
    [#393](https://github.com/feedback-loop-ai/brokkr/pull/393)
- **Policy.**
  - Decision 0050's audit reports its checks at compile.
    [#492](https://github.com/feedback-loop-ai/brokkr/pull/492)
  - A v2 rule refuses a key outside its nine, so a misspelt gate cannot
    vanish. [#382](https://github.com/feedback-loop-ai/brokkr/pull/382)
- **Roster.** `sonnet` is Claude Sonnet 5.5. `sol` is GPT-6.1 Sol, capped at
  high effort, and Astra is kept only as a chief's last fallback. DeepSeek's
  Flash is pinned by its current name.
  [#482](https://github.com/feedback-loop-ai/brokkr/pull/482),
  [#498](https://github.com/feedback-loop-ai/brokkr/pull/498),
  [#400](https://github.com/feedback-loop-ai/brokkr/pull/400)
- **The code is held to its architecture (decision 0071).** These gates run
  on every pull request, and the required ones run again on the merge
  queue's own commit.
  [#454](https://github.com/feedback-loop-ai/brokkr/pull/454)
  - **Ratchets** on function size, nesting, parameters, suppressions, CRAP,
    file size, duplication, public API and unused dependencies, against
    committed baselines.
  - **Static gates:** pure core and view crates, no `unsafe`, one-way
    layering, and known dependency sources.
  - **Exact coverage,** with its escapes closed.
  - **Mutation testing** of brokkr-core's diff.
  - **Deterministic budgets** for speed, memory, crate count, prompt bytes
    and binary size. The binary budget is a 30 MB ceiling.
  - **Non-Rust lints,** with every tool pinned.

## Known issues

- **A sandboxed script can park `indeterminate`.** A boxed exec attempt on a
  loaded host can park as indeterminate because a sandbox descendant was
  still exiting at the kill. Retry it.
  [#504](https://github.com/feedback-loop-ai/brokkr/issues/504)
- **Seats can receive cross-session messages.** On a host running other
  interactive Claude Code sessions, a seat is reachable by those sessions'
  cross-session messages: an input channel outside the journal.
  [#505](https://github.com/feedback-loop-ai/brokkr/issues/505)
- **Some quarantined runs never leave "needs you".** A run whose journal does
  not fold has no operator command that closes it.
  [#511](https://github.com/feedback-loop-ai/brokkr/issues/511)
- **The terminal can be left in raw mode.** If an external SIGTERM, SIGHUP or
  SIGQUIT arrives while a driven run view is open, run `reset`. Ctrl+C itself
  is handled.
- **Two commands cost more instructions.** Each crossed the CPU budget's 2%
  step in this cycle, measured against its pull request's base:
  `brokkr inspect` (+2.1%, #509) and `brokkr --version` (+2.8%, #510).
- **The status page and security model predate 0065.** They do not yet
  describe its tools semantics. Read decision 0065 for what a seat holds.
  [#366](https://github.com/feedback-loop-ai/brokkr/issues/366)

## Upgrade and compatibility

**Capability flags in a driver command are refused at compile.** A recipe or
agent that writes any of these into an inline driver command must declare
them as data instead:
- a tool list: `--allowedTools`, `--tools`, `--disallowedTools`;
- `--permission-mode`;
- an MCP, settings or config load: `--mcp-config`, `--strict-mcp-config`,
  `--settings`, Codex `-c`;
- a sandbox class: Codex `--sandbox` or `-s`;
- an extra directory: `--add-dir`;
- a session selector.

The refusal names the argument. Declare `tools.allow`, `tools.deny` or
`tools.sandbox` on the seat or its agent, and grant the capability in the
realm's map (`forge.realms/v6`, `capabilities`). `brokkr doctor` shows what
each seat ends up holding.

**Finish or conclude runs started before this release with 0.11.** A pinned
resume of such a run refuses as `unrecorded`, because its manifest records
none of the capabilities this release requires.

Also retired in this cycle:
- **The pre-rename names.** The `FORGE_*` environment overrides and the
  `{forge}` argv token no longer configure anything. Set the `BROKKR_*`
  names, and write `{brokkr}`.
  [#457](https://github.com/feedback-loop-ai/brokkr/pull/457)
- **`binding_grant` in an adapter is refused.** Declare `egress` instead.
- **`python3` and `pytest`** leave the shipped allow-lists.
- **`intake-sdd`** leaves the agent library.

**New contracts.** `realms.v6`, `run-manifest.v11`, `tool-dialect.v1` and
`effect-cleanup.v1` sit beside their earlier versions; no earlier frozen bytes
changed. The version bump changes compiled manifest identities. The binary
remains `brokkr`, with Rust 1.88 as the minimum build version.

**Verifying a download.** Check it against `SHA256SUMS`, and its build
provenance with `gh attestation verify <asset> -R feedback-loop-ai/brokkr`.
