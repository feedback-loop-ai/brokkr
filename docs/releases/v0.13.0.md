# v0.13.0 “Járngreipr”: MCP tools a seat grips through Brokkr's own broker, a journal read a page at a time, and one folder for Brokkr in every repository

> *Gloves are not done when they fit the carving. They are done when the
> hand that will use them can approach, greet, grip and release.*
>
> — [The Lay of the Gloves](../lore/sagas/the-lay-of-the-gloves.md)

Járngreipr are Thor's iron gloves, which, the Edda says, he cannot do
without when he lays hold of the hammer's haft. v0.12.0 “Gleipnir” bound
capabilities to the realm. In this release a seat actually grips a granted
tool: on Linux, a realm can grant a Claude seat an MCP server, and the seat
calls it only through Brokkr's own broker. The release also reads the
journal a page at a time, keeps an adopter's Brokkr in one `.brokkr/`
folder, and adds a run queue, journal backups and boxed hands for dsh. It
includes the changes merged since
[v0.12.0](https://github.com/feedback-loop-ai/brokkr/releases/tag/v0.12.0).

**This release refuses an adopter repository still in the 0.12 layout,
stops seats on Linux from starting your own MCP servers, and parks a
timed-out attempt instead of retrying it.** Read
[Upgrade and compatibility](#upgrade-and-compatibility) before you install
it over a working setup.

## What changed

- **MCP tools, through Brokkr's own broker (decision 0065, slice two).**
  - **Granting a server.** Write a tool dialect of kind `mcp` (a stdio
    server's argv, its pinned version and its tools), and grant it in the
    realm map's `capabilities`. For each capability a seat holds, the
    engine adds a `cap-<capability>` server beside the box's `workspace`
    hands. The harness starts it as `brokkr broker serve`, Brokkr's broker
    (decision 0077). `brokkr doctor` shows each seat's whole capability
    plan.
  - **Each server in its own box.** The broker runs the real server in a
    box of its own: its program read-only, a private home and temp
    directory, no workspace, a cleared environment, and only the network
    its egress class allows.
  - **The broker is the gate.** It lists only the granted tools, refuses
    any other call by name, and masks every bound secret in a response.
    Each call is in the attempt's ledger before it is forwarded or
    refused, and lands in the journal as a `seat-record.v6` checkpoint when
    the attempt settles.
  - **Kept responses.** A dialect may keep its responses, and the realm may
    veto that with `retain: false` (`forge.realms/v8`).
    `brokkr inspect --run <run> --capability-call <id>` opens a kept
    response, verified against its digest.
  - **No ambient MCP on Linux.** Every model seat is launched with only the
    servers Brokkr names: none, the box's hands, or its brokers. Your own
    MCP configuration no longer reaches a seat. A harness not measured to
    shut it out is refused at compile, and the final launch check refuses
    a server set that differs from the sealed one.
  - **A real seat, end to end.** A real Claude seat holding a grant
    completed a run, and its call's response read back through
    `brokkr inspect`. On the way, the broker learned to answer any MCP
    `initialize` with its own version (2025-06-18), a brokered Claude
    launch allows each broker as `mcp__cap-<capability>`, and the broker
    closes its ledger on SIGINT or SIGTERM.
  - **Host checks.** `brokkr driver` sets `no_new_privs` before a brokered
    harness, and refuses where it cannot. MCP servers refuse to start where
    `/proc/sys/dev/tty/legacy_tiocsti` is absent or not `0`.
  - **One run per worktree, for every run.** Every dispatched attempt
    reserves its sites, whether or not it brokers anything. A second run
    whose writers would reach a worktree that a standing attempt writes is
    refused until the first is proven settled. `brokkr operator release`
    journals your attestation that a run's ended attempts left no process,
    and frees the worktree. Where HOME does not resolve to a protected
    coordination root, an attempt that protects no evidence proceeds
    unreserved, and one that does refuses.
  - **Harder boxes.** Every workspace box hides the secrets store and opens
    in a user namespace that can make no further one.
  - **Limits.** Linux only: on macOS every `mcp` grant still refuses at
    compile. Claude only: a brokered grant on a Codex or dsh seat refuses
    at compile. The seat needs workspace hands under `namespace`, with the
    network off. A server may bind a secret on a Claude work seat: Claude
    Code 2.1.316's boxed replacement session is measured.
    [#958](https://github.com/feedback-loop-ai/brokkr/pull/958) URL
    connections, secrets in the argv and nonempty restrictions refuse.
  - **Documented.** The guides, the status page and the security model say
    what this slice built, and what it did not.
    [#956](https://github.com/feedback-loop-ai/brokkr/pull/956)
  - **Audited.** Before this release, every piece of slice two was checked
    against its removals, its proofs and the frozen contract bytes. The
    audit changed no production code.
    [#963](https://github.com/feedback-loop-ai/brokkr/pull/963)

- **A journal read a page at a time (decision 0089).** On a 1.1 GB journal,
  0.12.0's console held 2.6 GB and `brokkr runs --json` took 6.7 s. A page
  now costs the same at any journal size.

    `brokkr doctor` checks them against a fresh fold.
  - **The fleet.** The console (`brokkr tui`), `brokkr runs` and
    `/api/runs` read a page of summary rows at a time; `brokkr runs` takes
    `--limit` and `--after`. The console refreshes only what landed since,
    off the input loop (decision 0088).
  - **One run.** A run is opened by verifying its chain one event at a
    time, and a corrupt run is refused as before. `inspect`, `seats`,
    `watch`, `transcript`, `costs`, `compare` and `/api/view` read through
    the pages and print the same bytes. The run view's first screen costs
    15 ms and 250 KB at any journal size.
  - **The console's run screens** read pages too. A movement key pressed
    while a page loads is held, in order, and applied when that page
    arrives, so the cursor moves exactly as it would on a whole read. A
    held key belongs to the view it was pressed on, and is dropped if that
    view leaves the frame (a narrower or shorter terminal, or another run,
    seat or tab). The queue holds 64 runs of keys; an overflow drops the
    oldest and says so.

## Upgrade and compatibility

**An adopter repository in the 0.12 layout is refused.** A repository that
0.12's `brokkr init` scaffolded, with its bundle and `.forge/` at the root,
is refused, and the refusal lists the moves into `.brokkr/`. It lists them
only for a clean tree, and none when a symbolic link stands under
`.forge`. Make the moves, commit, and run `brokkr doctor`. Until then,
`--db` still reads the old journal in place. A recipe library keeps its
layout.

**On Linux, seats no longer start your own MCP servers.** Every model seat
(Claude, Codex and dsh; not an exec seat) is served only its isolated set:
nothing, its hands, or its brokers. So the servers in your Claude Code or
Codex configuration, or your dsh home, never start, grant or no grant. A
seat whose shape is not measured on Linux (an unmeasured shape, or a dsh
route outside the measured ones) now refuses with the isolation check's
cause instead of running. A driver you run by hand, with no sealed intent,
is served as before. If a seat relied on one of your servers, grant it
through the realm instead; today that works for a Claude seat with
workspace hands, including a server that binds a secret. A Codex seat refuses on a host that
holds `/etc/codex/config.toml` or `/etc/codex/managed_config.toml`.

**Linux hosts need bubblewrap 0.11 and Linux 5.11.** A seat that binds an
overlay, as the shipped recipes' cache binds do, needs bubblewrap 0.11.
Every boxed launch needs Linux 5.11, for `close_range` with
`CLOSE_RANGE_CLOEXEC`. A nested `unshare -U` or bubblewrap inside a box now
fails.

**Timed-out attempts park.** A deadline kill or a lost result parks the run
`indeterminate` instead of retrying. Check what the attempt did, then
`brokkr operator retry` it or `brokkr conclude` the run.

**Two endings announced in 0.12.0 arrive.**
- **A hands tree with no lock file is kept.** A tree under the temporary
  directory that holds no lock file is now kept and reported, never
  reaped. The report reads: "hands: kept <tree>: its lock cannot be
  probed: it holds no lock file; trees from before #415 are no longer
  reaped (0.13.0)". Once no older engine is using such a tree, remove it
  yourself. ([#415](https://github.com/feedback-loop-ai/brokkr/issues/415))
- **`brokkr_protocol::hands::box_argv` is removed.** It was deprecated in
  0.12.0, and its retirement this cycle made it refuse every call. A Rust
  caller runs a box through `hands::run_boxed` or `hands::execute`.

**Your own policy tables must rule every case.** Compile now refuses the
tables above, naming the ruling. Add a named park for a residual rated
none, as the shipped `REVIEW-RESIDUAL-NONE` does, before you move a host to
0.13.

**Recipes moved.** `bundles/self` and `bundles/verify` are now
`recipes/self` and `recipes/verify`, and `brokkr recipes list` lists the
library only. Outside a folder, `fast`'s verify fails closed and runs no
check; Brokkr's own verifier is `brokkr-fast`.

**Finish or conclude 0.12 runs with 0.12.** Every compiled bundle's digest
moved, so a pinned resume of a run started under 0.12.0 refuses.
`brokkr conclude` closes one from its journal alone.

**The journal migrates itself.** The first 0.13 writer to open a journal
backfills the projections, one run at a time; on journals of over a
gigabyte this took seconds. A read-only open migrates nothing.
`event_schema`, `database_schema` and `driver_protocol` all stay 1.

**Before a run that keeps MCP evidence, let older engines finish.** An
engine older than 0.13 takes no worktree lease, so 0.13 cannot see it.

Also changed in this cycle:
- The secrets store must stay owner-only, as `brokkr secrets set` creates
  it; a workspace box refuses a store with group or other permission bits.
- An office that declares no `access` beside its hands reads as `writes`.
- `/api/run/<id>` is retired; read `/api/view`. Scripts that read `--json`
  see `view_version` 28, where 0.12.0 wrote 15.
  [#623](https://github.com/feedback-loop-ai/brokkr/pull/623)

**New contracts.** `realms.v7`, `realms.v8`, `run-manifest.v12` to `v14`,
`seat-record.v6`, `host.v1` and `panel-carry.v1` sit beside their earlier
versions; no earlier frozen bytes changed. The binary remains `brokkr`,
with Rust 1.88 as the minimum build version.

**Verifying a download.** Check it against `SHA256SUMS`, and its build
provenance with `gh attestation verify <asset> -R feedback-loop-ai/brokkr`.

## Known issues

- **On macOS, seats still start your own MCP servers.** The MCP fence is
  set per host at build time: it stands on macOS, where every `mcp` grant
  refuses, and no shape is measured there, so a seat is served as in 0.12
  and starts your user-scope servers. On every host, a Claude seat loads your settings,
  `CLAUDE.md` and hooks.
  [#467](https://github.com/feedback-loop-ai/brokkr/issues/467)
- **Seats can receive cross-session messages** from other interactive
  Claude Code sessions on the host.
  [#505](https://github.com/feedback-loop-ai/brokkr/issues/505)
- **A boxed dsh hands seat has not run end to end through `brokkr driver`
  on a measured route,** because the driver's route grammar refuses that
  route as configured.
  [#953](https://github.com/feedback-loop-ai/brokkr/issues/953)
- **A large panel that keeps MCP evidence can park under load.** Each
  member surveys the host inside one 30-second startup bound; a 32-member
  panel parked at a load near 6.
- **A boxed exec attempt can still park `indeterminate`, rarely:** one in
  40 stressed runs. Retry it.
  [#504](https://github.com/feedback-loop-ai/brokkr/issues/504)
- **A journal path that begins `file:` is read as a SQLite URI** by
  `--db` and a map's `journal`. Give journals absolute paths.
  [#954](https://github.com/feedback-loop-ai/brokkr/issues/954)
- **dsh seats still cannot commit,** and keep dsh's own web search and
  fetch. [#282](https://github.com/feedback-loop-ai/brokkr/issues/282),
  [#462](https://github.com/feedback-loop-ai/brokkr/issues/462)
