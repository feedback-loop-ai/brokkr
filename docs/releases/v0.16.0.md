# v0.16.0 “Draupnir”: Antigravity CLI joins as a trusted harness and Qoder CLI as a provisional one, an entry starts when its recipe's measured demand fits what the machine has free, the command line nests into thirteen roots and completes itself, and a boxed dsh seat with workspace hands launches again

Draupnir is the gold ring that Brokkr and his brother forged next after
Gullinbursti. Every ninth night, eight rings of its own weight drop from
it. This release is about one engine from which new harnesses come at
equal standing: Antigravity CLI and Qoder CLI arrive as adapter data and
a driver kind, and are judged by the same rules as the harnesses before
them.

- **Two new harnesses.** Antigravity CLI (`agy`) is trusted, its four
  Gemini 4 models are promoted, and Neon and Carbon are its judges. An
  agy seat can hold boxed hands, never starts agy's self-updater, and
  keeps its transcript past its turn, readable in the run view. Qoder
  CLI is a provisional harness.
- **Admission by measured demand.** An entry starts when its recipe's
  measured demand, beside what running runs still reserve, fits what
  the machine has now (decision 0125).
- **A nested command line that completes itself.** Brokkr's visible
  commands nest into thirteen roots — decision 0113's twelve plus
  `completions` from decision 0119 — and `brokkr completions <shell>`
  and a live completer complete them.
- **A boxed dsh seat with workspace hands launches again** (#1277).

It includes the changes merged since
[v0.15.2](https://github.com/feedback-loop-ai/brokkr/releases/tag/v0.15.2).

**Read [Upgrade and compatibility](#upgrade-and-compatibility) before
you upgrade.** Opening a journal at queue storage v1 to v5 for writing
migrates it to v6 (refused by a v5-only engine afterwards); a v6 journal
from 0.15.2 is not migrated further, but rows 0.16.0 writes to it can be
unreadable to 0.15.2. The old flat command spellings still work in 0.16
and go in 0.17, except `dispatch drive`, which stays until no live
pre-0.16 dispatcher can still spawn it. The queue now orders by priority
first, and where the machine's availability is measured, admission
judges an entry by its demand.

## What changed

Each entry below is a summary. The decision, guide or pull request it
links holds the full rule and its exceptions; where the two differ, the
linked record governs.

### Harnesses

- **Antigravity CLI is a trusted harness**
  ([#1200](https://github.com/feedback-loop-ai/brokkr/issues/1200),
  [#1283](https://github.com/feedback-loop-ai/brokkr/pull/1283);
  [#1252](https://github.com/feedback-loop-ai/brokkr/issues/1252),
  [#1314](https://github.com/feedback-loop-ai/brokkr/pull/1314)).
  - **The driver.** `brokkr driver agy` runs Antigravity CLI 1.5 as one
    stream-json turn read from stdin. It runs under a HOME the engine
    makes for that turn alone, with the operator's login linked in, and
    removes that HOME after the turn. A seat that binds `HOME` is
    refused. `BROKKR_AGY_BIN` overrides the binary.
  - **The adapter** ships as an example,
    [`docs/examples/adapters/agy.json`](../examples/adapters/agy.json),
    which a world copies into its adapters directory. It declares agy
    `trusted`, maps the four Gemini 4 models as promoted, and names
    `agy-neon` and `agy-carbon` its judges. Its route is class
    `contracted` (decision 0036's note of 2026-11-20). Decision 0021's
    addendum of 2026-11-22 records the ruling, with the wagers' run ids.
  - **What it refuses.** A seat whose served model is not exactly its
    pin is refused. A turn agy stopped at a denial is never read as an
    answer. One `PreToolUse` hook, `brokkr driver agy -- --gate`, denies
    every tool outside the level-1 list, web search included. A
    workspace carrying agy's own `.agents` configuration in the working
    directory or any directory above it is refused before agy starts.
  - **The guide:** [provider
    adapters](../guides/provider-adapters.md#antigravity-cli-a-trusted-harness).
- **An agy seat can hold boxed hands**
  ([#1224](https://github.com/feedback-loop-ai/brokkr/issues/1224),
  [#1283](https://github.com/feedback-loop-ai/brokkr/pull/1283)).
  - A boxed launch leaves the model one tool, the engine's workspace
    tool, and there is no `--mode accept-edits`. A boxed gate compiles
    on a model the adapter names a judge, and is refused on any other.
  - Agy's own process still runs on the host. Its native tools are
    switched off by agy's hook, not by the operating system. A boxed
    seat that passes `--allow` is refused before agy starts, and so is a
    launch under a boxing boundary whose hands were not served.
  - The boxed shapes are measured on Antigravity CLI 1.5.14 on Linux.
    On macOS nothing is measured for agy, and a boxed agy seat does not
    launch ([the guide](../guides/provider-adapters.md#a-boxed-agy-seat)).
- **An agy seat never starts agy's self-updater** (decision 0124,
  proposed; [#1224](https://github.com/feedback-loop-ai/brokkr/issues/1224)).
  Every agy child carries `AGY_CLI_DISABLE_AUTO_UPDATE=true`, and a seat
  that binds that name is refused.
- **An agy seat's transcript is kept past its turn and is readable in
  the run view**
  ([#1227](https://github.com/feedback-loop-ai/brokkr/issues/1227),
  [#1377](https://github.com/feedback-loop-ai/brokkr/pull/1377);
  decision 0075 level 2, its addendum of 2026-11-24, proposed).
  - **Where.** Before the engine HOME is removed, the driver copies
    agy's conversation transcript to
    `~/.local/state/brokkr/agy-conversations/<id>/transcript.jsonl`, in
    a 0700 directory, as a 0600 file of at most 32 MiB. The seat
    records the kind `agy-conversation`.
  - **When nothing is kept.** On a refusal to start, a probe, a missing
    or non-UUID conversation id, a source that is a link, not a regular
    file or over 32 MiB, a reference the run view's path rule rejects,
    or an emitted seat-record reference row that masking would alter.
    Masking is checked on that emitted reference row, not on the
    transcript's content; bound values inside the transcript's content
    can still be kept in the owner-only file.
  - **Reading it.** `brokkr runs transcript`, the TUI and the browser
    read the kept file in file order, and mask its timestamps and text
    as they do every transcript kind's. The kept file itself is
    unmasked and readable only by the operator's user.
  - **Not yet.** Rejoining an agy conversation is unsupported, and
    nothing removes kept conversations yet
    ([#1323](https://github.com/feedback-loop-ai/brokkr/issues/1323)).
    See [Known issues](#known-issues) for #1375.
- **Qoder CLI is a provisional harness**
  ([#1178](https://github.com/feedback-loop-ai/brokkr/issues/1178),
  [#1258](https://github.com/feedback-loop-ai/brokkr/pull/1258)).
  - `brokkr driver qoder` runs Qoder CLI 1.1 in print mode with a fixed
    tool list, the prompt on stdin and no session kept.
    `BROKKR_QODER_BIN` overrides the binary.
  - The adapter ships as an example,
    [`docs/examples/adapters/qoder.json`](../examples/adapters/qoder.json).
    It maps five provisional models, holds no gate, declares no hands
    and is never resumed.
  - A seat whose served model is not exactly its pin is refused, and so
    is a signed-out CLI (decision 0075's addendum of 2026-11-21).
  - Its MCP isolation is measured on Linux, so a qoder seat compiles
    there
    ([the guide](../guides/provider-adapters.md#qoder-cli-a-provisional-harness)).
- **Seat-record v8 opens the transcript kind and the root session kind**
  ([#1227](https://github.com/feedback-loop-ai/brokkr/issues/1227),
  [#1282](https://github.com/feedback-loop-ai/brokkr/pull/1282);
  decision 0075's addendum of 2026-11-21, accepted).
  - An adapter declares the kinds its seats record and the resume shape
    they rejoin by. Nothing acts on a kind its harness did not declare.
  - v8 is written for the runs a 0.16.0 engine starts. It stands beside
    v7, which adds a gate's typed findings, and v6, which earlier runs
    keep.
- **A fold reads a harness row's structure as the harness wrote it, and
  its text only masked** (decision 0114, accepted;
  [#1242](https://github.com/feedback-loop-ai/brokkr/issues/1242)).
  - **Before:** a bound secret value that occurred inside a protocol
    word, such as `type` or `result`, was masked out of the row before
    the fold read it. A turn could then read as a refusal, or a
    provider's refusal could be hidden.
  - **Now:** the shared fold, Claude, Codex, dsh and Qoder read each
    row's structure raw through one row reader, and quote its text only
    masked
    ([#1315](https://github.com/feedback-loop-ai/brokkr/pull/1315),
    [#1326](https://github.com/feedback-loop-ai/brokkr/pull/1326),
    [#1331](https://github.com/feedback-loop-ai/brokkr/pull/1331),
    [#1342](https://github.com/feedback-loop-ai/brokkr/pull/1342)).
  - **Claude and Codex rows** reach a turn's timestamp and role only in
    a closed shape
    ([#1340](https://github.com/feedback-loop-ai/brokkr/issues/1340),
    [#1371](https://github.com/feedback-loop-ai/brokkr/pull/1371)).
- **A boxed dsh seat with workspace hands launches again**
  ([#1277](https://github.com/feedback-loop-ai/brokkr/issues/1277),
  [#1364](https://github.com/feedback-loop-ai/brokkr/pull/1364);
  decision 0127, proposed).
  - **Before:** dsh's `--dump-config` folded the long JSON `--reach` and
    `--spec` values onto lines the driver's line rule refuses, so the
    seat could not launch.
  - **Now:** the dsh overlay carries those exact bytes as unpadded
    base64url, under `--reach-base64url` and `--spec-base64url`.
    `brokkr hands serve` accepts either spelling of each document and
    parses both through one path, so both admit and refuse the same
    documents. An encoded refusal never echoes the value. Other
    harnesses' MCP configurations are unchanged
    ([hands reference](../reference/hands.md)). Its follow-up is
    [#1378](https://github.com/feedback-loop-ai/brokkr/issues/1378).

### Admission and the queue

- **An entry starts when its recipe's measured demand fits what the
  machine has now** (decision
  [0125](../decisions/0125-an-entry-starts-when-its-recipes-measured-demand-fits-what-the-machine-has-now.md),
  accepted; [#1193](https://github.com/feedback-loop-ai/brokkr/issues/1193):
  [#1346](https://github.com/feedback-loop-ai/brokkr/pull/1346),
  [#1369](https://github.com/feedback-loop-ai/brokkr/pull/1369)).
  - **What is measured, on every pass.** On Linux, `MemAvailable` and
    the idle cores over 500 ms. On macOS, free plus reclaimable pages
    and the idle cores, with kernel memory pressure at warn or critical
    as a veto. Each running run's driver tree is measured too.
  - **What is learned.** A recipe's demand is the largest of its
    phases' mean peaks over its last 20 measured runs, plus a 25%
    margin. The window gives a profile only once one of its runs has
    completed. The host file may override both numbers, and may declare
    a recipe's demand.
  - **The rule.** After decision 0068's checks, an entry waits as
    `memory_short`, `cpu_short`, `memory_pressure` (macOS) or
    `demand_unknown`, each naming its numbers. An entry whose recipe has
    no profile and no declaration starts only when nothing else runs. An
    entry whose demand exceeds a resource's total capacity (`MemTotal`
    or every core) also starts on an idle pass when the other resource
    check passes, and waits as `memory_short` or `cpu_short` naming the
    whole machine otherwise (decision 0125 ruling 6). `brokkr queue list`
    and its `--json` show the demand an entry was judged by.
  - **The host file.** `forge.host/v5` makes the run and boxed-build
    ceilings optional and adds a `demand` block. Every v1 to v4 file
    reads as it did. `brokkr system host upgrade` moves a file to v5 by
    its schema token alone, and `--check` previews the move. `brokkr
    init` writes a v5 file with placeholder ceilings only where the
    machine has none ([read surfaces](../guides/read-surfaces.md)).
  - **Measured first.** A seat attempt records the CPU and memory its
    process tree used as optional `effect-usage.v1` data whenever a
    100 ms sampling tick reads its process tree — an attempt no tick
    reads records no usage — and `brokkr library recipes usage` shows
    each recipe's phases by min, average and max (decision 0112
    ruling 3, accepted;
    [#1208](https://github.com/feedback-loop-ai/brokkr/pull/1208)).
- **The queue orders by priority first, then place**
  ([#1191](https://github.com/feedback-loop-ai/brokkr/issues/1191),
  [#1254](https://github.com/feedback-loop-ai/brokkr/pull/1254)).
  `queue move` orders an entry within its priority, and prints the place
  its command journaled.
- **An entry can wait on a named ending or on a merge**
  ([#1192](https://github.com/feedback-loop-ai/brokkr/issues/1192),
  [#1303](https://github.com/feedback-loop-ai/brokkr/pull/1303)).
  `--after 3:shipped` waits for entry 3's run to end shipped, and any of
  decision 0064's other endings except `unclassified` may be named
  (`WaitOn::ALL` excludes `unclassified`, so `--after 3:unclassified` is
  refused). `--after 3:merged` waits for the operator's journaled
  `brokkr queue merged 3 --reason …`. Brokkr reads no code host, so that
  record is the merge's one witness.

### The command line

- **The visible commands nest into thirteen roots** (decision
  [0113](../decisions/0113-brokkr-s-root-commands-nest-into-twelve-roots.md),
  accepted, for the twelve roots below, plus `completions` added as the
  thirteenth root by decision 0119 ruling 1;
  [#1169](https://github.com/feedback-loop-ai/brokkr/issues/1169):
  [#1246](https://github.com/feedback-loop-ai/brokkr/pull/1246),
  [#1276](https://github.com/feedback-loop-ai/brokkr/pull/1276)).
  - `init`, `run`, `resume`, `watch`, `tui` and `doctor` stay at the
    root, joined by `completions` (below). `runs`, `journal`, `library`,
    `queue`, `stats` and `system` hold the rest. For example, `brokkr
    inspect` is now `brokkr runs inspect`, `brokkr dispatch` is `brokkr
    queue dispatch`, and `brokkr ledger` is `brokkr stats ledger`.
  - A bare `brokkr runs` still lists runs.
  - Every spelling the binary prints, the guides and the CLI reference
    use the new tree. For the old spellings, see [Upgrade and
    compatibility](#upgrade-and-compatibility).
- **Brokkr completes its own command line** (decision
  [0119](../decisions/0119-brokkr-completes-its-own-command-line.md),
  accepted; [#1230](https://github.com/feedback-loop-ai/brokkr/issues/1230),
  [#1284](https://github.com/feedback-loop-ai/brokkr/pull/1284)).
  - `brokkr completions <shell>` prints a static script for bash, zsh,
    fish, powershell or elvish: every visible verb, flag and fixed value.
  - `source <(COMPLETE=bash brokkr)` registers the live completer, which
    also offers run ids, phases, seats, recipes, agents, realms and queue
    entries. It only reads.
  - The Homebrew formula installs the live completer for bash, zsh and
    fish ([#1305](https://github.com/feedback-loop-ai/brokkr/issues/1305),
    [#1308](https://github.com/feedback-loop-ai/brokkr/pull/1308)).
  - The steps for each shell are in the
    [quickstart](../guides/quickstart.md).
- **`brokkr stats graph` prints its states and rules as two aligned
  tables** ([#1167](https://github.com/feedback-loop-ai/brokkr/issues/1167),
  [#1207](https://github.com/feedback-loop-ai/brokkr/pull/1207)), where it
  printed one `·`-separated line each. They fit `COLUMNS`, else the
  window of the stdout they are written to, else 80 cells. `--json` and
  `NO_COLOR` are unchanged.

### Gates, verdicts and secrets

- **A gate's word is bound to its findings** (decision 0109 slices
  0109a1 and 0109a2;
  [#1088](https://github.com/feedback-loop-ai/brokkr/issues/1088):
  [#1216](https://github.com/feedback-loop-ai/brokkr/pull/1216),
  [#1222](https://github.com/feedback-loop-ai/brokkr/pull/1222),
  [#1237](https://github.com/feedback-loop-ai/brokkr/pull/1237),
  [#1243](https://github.com/feedback-loop-ai/brokkr/pull/1243)).
  - A gate's findings and the head it checked are engine-stamped:
    seat-record v7 introduced those fields, and runs started by 0.16.0
    write seat-record v8, which carries them forward.
  - A security finding requires `security-hold`, and a blocking finding
    refuses a passing word. The word is refused, never rewritten.
  - A unanimous-pass panel under a seat that declares the residual pair
    could never pass, so the compiler now refuses it.
  - The five review charters say what decision 0109 binds on a
    verdict's word and its findings
    ([#1322](https://github.com/feedback-loop-ai/brokkr/issues/1322),
    [#1349](https://github.com/feedback-loop-ai/brokkr/pull/1349)).
- **A capability call the seat's bindings rewrote fails closed**
  ([#1261](https://github.com/feedback-loop-ai/brokkr/issues/1261),
  [#1280](https://github.com/feedback-loop-ai/brokkr/pull/1280)). A
  checkpoint whose keys, or whose observed tool name, hold a secret
  marker is refused as unattributable. Before, a binding inside a native
  tool's name could let an unheld call go unrefused.
- **Overlapping secret values are both masked**
  ([#1213](https://github.com/feedback-loop-ai/brokkr/issues/1213),
  [#1253](https://github.com/feedback-loop-ai/brokkr/pull/1253);
  decision 0012's addendum of 2026-11-21, accepted). Every byte that any
  occurrence of any bound value covers is masked. Before, two bound
  values that overlapped could leave part of one in clear.
- **The journal names a driver's stderr only by content-free evidence**
  ([#1199](https://github.com/feedback-loop-ai/brokkr/issues/1199),
  [#1249](https://github.com/feedback-loop-ai/brokkr/pull/1249);
  decision 0012's addendum of 2026-11-20, accepted).
  - **Before:** a failed or indeterminate attempt journaled the last
    2000 characters of its driver's stderr, masked only by the seat's
    own bindings.
  - **Now:** the journal holds the stderr's length, the class of its
    first byte and a SHA-256 prefix. The masked tail goes to the
    engine's stderr: the driver log under dispatch, the terminal under
    `run` and `resume`. Old journals keep their tails.
  - Stderr evidence masks each bound value's raw and stripped
    occurrences through one offset map
    ([#1361](https://github.com/feedback-loop-ai/brokkr/pull/1361)).

## Upgrade and compatibility

- **Journals: v1 to v5 journals migrate to v6 on write, and stay on
  0.16.0 once it has written to any journal.**
  - **What 0.16.0 does to a journal.** The database schema (1), the
    queue storage (6) and the event schema (1) are 0.15.2's. Opening a
    journal at queue storage v1 to v5 for writing migrates it to v6
    (decision 0104 ruling 8, `5904ce25b`), after which a v5-only engine
    refuses the queue. A journal already at v6 (which 0.15.2 writes and
    understands) undergoes no further schema migration; measured on this
    candidate, a v6 journal that 0.15.2 created and 0.16.0 then wrote to
    without the new rows below still lists under 0.15.2.
  - **What 0.15.2 refuses or ignores afterwards.** Separately from schema
    migration, 0.15.2 already understands queue storage v6, but 0.16.0
    writes new row values that 0.15.2 does not know:
    - a queue wait on a named ending or on `merged` (`79c3303ec`):
      0.15.2's `queue list` refuses the journal because
      `queue_waits.condition` holds a value it does not know (measured:
      after 0.16.0 queued an entry `--after 1:shipped`, 0.15.2's
      `queue list` refused with `queue column queue_waits.condition
      holds 'shipped', which this brokkr does not know`; a wait on
      `merged` is refused the same way);
    - a standalone `brokkr queue merged` command: it writes a `'merged'`
      row in `queue_commands` without changing `queue_entries`, and the
      merge marker satisfies `merged` waits without changing the
      displayed state (both 0.16.0 and 0.15.2 display `claimed`). On an
      otherwise readable v6 journal, 0.15.2's `queue list` does not
      refuse it — it ignores the `'merged'` command row and still
      displays `claimed`, unaware of the merge marker;
    - the seat records of a run that 0.16.0 started. They are written
      under seat-record v8, and 0.15.2 judges them against v6.
  - **What to do.** Before you upgrade, back each journal up with the
    binary you run today (`brokkr backup` in 0.15). Once 0.16.0 has
    written to a journal, do not go back to a 0.15 engine on it; to go
    back, restore the backup. Bundle digests cover the engine version,
    so a run started under 0.15.x resumes only under 0.15.x's binary,
    as before.
- **The command line.**
  - **The old flat spellings still work in 0.16.0.** Each root that
    moved — see decision
    [0113](../decisions/0113-brokkr-s-root-commands-nest-into-twelve-roots.md)
    ruling 1 for the full old-to-new inventory, including verbs whose
    leaf name changed such as `verify-run` to `journal verify` — still
    parses as the same command with the same arguments. It is hidden
    from `--help`, and it prints one line on stderr first:
    `brokkr: 'inspect' is now 'brokkr runs inspect'; the old spelling goes in 0.17`.
    Between an alias and its nested spelling, stdout is unchanged, so
    `--json` output is byte for byte the new spelling's.
  - **0.17 removes them, with one exception** (decision 0113 ruling 6).
    Move your scripts to the new spellings now. The rename itself leaves
    exit codes, `--json` documents and every flag's name and meaning
    unchanged (decision 0113 ruling 5). Across releases, however,
    `brokkr queue list --json` adds an optional `demand` object on each
    entry sized by a measured pass (decision 0125 ruling 8), which
    breaks strict 0.15.2 JSON consumers that reject unknown fields. The
    exception is `dispatch drive`: a live pre-0.16 dispatcher can still
    spawn `dispatch drive`, so that alias must survive until no live
    pre-0.16 dispatcher can still spawn it.
  - **Not moved:** `driver`, `hands`, `bridge`, `broker`, `fake-driver`
    and `dsh-sandbox-runner` stay hidden at the root. `dispatch drive`
    is now `queue dispatch drive`; a dispatcher from before 0.16 still
    spawns `dispatch drive`, which reaches 0.16.0 through its alias.
  - **The dsh console extension** under `extensions/dsh/brokkr-console`
    keeps 0.15's spellings until 0.17
    ([dsh console](../guides/dsh-console.md)).
- **The queue orders by priority first.** An entry queued at a higher
  `--priority` now starts before an earlier, lower one. `queue move`
  places an entry only among those of its own priority.
- **Admission.**
  - **Where availability is measured**, on Linux and macOS, a host file
    that declares no run ceiling (`forge.host/v1` to `v3`, or a `v5`
    without one) no longer holds every entry as `runs_undeclared`.
    Entries are judged by demand, and a declared ceiling is still
    obeyed.
  - **New wait reasons.** An entry may now wait as `memory_short`,
    `cpu_short`, `memory_pressure` or `demand_unknown`. A recipe with no
    completed measured run waits for an idle machine until one of its
    runs completes. Declare its demand in the host file to size it
    sooner. An entry whose demand exceeds a resource's total capacity
    (`MemTotal` or every core) still starts on an idle pass when the
    other resource check passes, rather than waiting forever.
  - **The host file.** An existing file reads as before, and `brokkr
    init` leaves it as it is. `brokkr system host upgrade --check` shows
    the move to v5, and `brokkr system host upgrade` makes it.
- **Gates.** A recipe whose unanimous-pass panel stands under a seat
  that declares `max_residual_severity` or `has_security_residual` no
  longer compiles. A gate whose passing word carries a blocking or a
  security finding is refused, where before it was taken.
- **A driver's stderr** no longer reaches the journal. Read it in the
  driver log under dispatch, or on the terminal under `run`.
- **Contracts.** New versions stand beside the frozen ones, and none is
  edited: `seat-record.v7`, `seat-record.v8`, `host.v5` and
  `effect-usage.v1`. The event schema (1), database schema (1), queue
  storage (6) and driver protocol (1) versions are unchanged; the engine
  version moves from `0.15.2` to `0.16.0`.
- **The crates' public API grew, with source-breaking changes** (the
  baselines are in [`quality/public-api/`](../../quality/public-api/)).
  Closed enums carry no `#[non_exhaustive]` (decision 0071 ruling 2), so
  new enum variants require new arms in downstream exhaustive matches;
  likewise, public structs carry no `#[non_exhaustive]`, so added fields
  break existing full struct literals and exhaustive destructuring.
  - **brokkr-core (source-breaking):** `RunState` gains
    `ending_step` and `step_records` (breaking existing full literals
    and exhaustive destructuring). Also a new `findings` module (the
    typed `Finding`, `FindingId`, `Covered` and `CheckedHead`, the word
    and residual checks `bind`, `admit` and `admit_live`, and their
    refusals), `fold::StepObservation` and `StepRecords`,
    `policy::CHANGE`, and the agy transcript constants and path checks
    in `seat`.
  - **brokkr-protocol (source-breaking):** new closed-enum variants
    `AdapterKind::Agy`, `AdapterKind::Qoder`, `Override::AgyBin` and
    `Override::QoderBin` (downstream exhaustive matches must add arms
    for them) and a new `AttemptReport::usage` field (breaking existing
    full literals and exhaustive destructuring), plus
    `DeclaredTranscriptKind`, `AttemptUsage`, `process::usage`
    (`trees_now`, `TreeNow`, `MemoryPressure`), `process::DriverStderr`,
    the hands base64url helpers and option names, the typed
    `hands::BindRefusal` and `SpecRefusal`, and `driver_kind`.
  - **brokkr-view (source-breaking):** new closed-enum variant
    `TranscriptKind::AgyConversation` (downstream exhaustive matches on
    `TranscriptKind` must add an arm for it) and a new
    `Projection::notices` field (breaking existing full literals and
    exhaustive destructuring), plus `GateRecord`, `GateFinding`,
    `gate_records`, `ResultNotes` and `result_notes`, `PhaseUsage`,
    `Spread`, `recipe_usage`, and `participant_label`.
  - **brokkr-cli (source-breaking):** `HandsCommand::Serve`'s `reach`
    and `spec` are now `Option<String>`, beside the new
    `reach_base64url` and `spec_base64url`.
  - **brokkr-runtime (source-breaking):** `admission::runs_undeclared`
    now returns `Option<Undeclared>`, not `Option<&'static str>`, new
    variants on `admission::Reason` (`Demand`, `EndedOtherwise` and
    `Unmerged` — downstream exhaustive matches on `admission::Reason`
    must add arms for them), `CompileError` and `LibraryError`, and new
    public fields
    on `Adapter` (`Adapter::record_kinds`), `Agent` (`results`),
    `Resolution` (`results`), `Bundle` (`declared_kinds`),
    `SequenceStep` (`declares_change`, `residual`), `admission::Host`
    (`machine`) and `admission::Judged` (`demand`), beside the admission
    types (`Machine`, `Available`, `Need`, `Reserved`, `Sized`, `Unfit`,
    `Source`, `Unmeasured`), `host_upgrade`, `measurable` and
    `CURRENT_HOST_SCHEMA`.
  - **brokkr-store (source-breaking):** `Store::queue_command` now
    returns the place it journaled (`Result<Option<u32>, _>`), new

    `QueueRefusal`, and new fields `EntryState::Claimed::merged` and

    reads, the engine-marker reads, and `WaitOn::ALL`, which now holds
    14 conditions.
  - **brokkr-bridge:** unchanged.

## Supported platforms

Linux x86_64 and aarch64, and macOS x86_64 and arm64 (decision 0063).
WSL2 is Linux. Qoder's and agy's isolation is measured on Linux alone:
on macOS nothing is measured for either, and a boxed agy seat does not
launch there.

## Install or upgrade

The GitHub release archives and `SHA256SUMS` are available as soon as
the GitHub release is published; crates.io, apt, rpm, Homebrew and Nix
follow as each channel publishes or merges its update pull request (for
example, `flake.nix` stays pinned to `0.15.2` until its channel pull
request merges; see the [README](../../README.md#install) for each
channel's command). Back your journals up first, as
[above](#upgrade-and-compatibility). The tarball path checks
`SHA256SUMS` before it unpacks:

```console
curl -LO https://github.com/feedback-loop-ai/brokkr/releases/download/v0.16.0/brokkr-linux-x86_64.tar.gz
curl -LO https://github.com/feedback-loop-ai/brokkr/releases/download/v0.16.0/SHA256SUMS
sha256sum --ignore-missing -c SHA256SUMS && tar xzf brokkr-linux-x86_64.tar.gz
```

A standing 0.15 `brokkr dispatch` ends at its next pass once its binary
is replaced, as [v0.15.0](v0.15.0.md) says of a replaced binary. Start
`brokkr queue dispatch` under 0.16.0 in its place.

## Known issues

- **Two macOS test failures bounce CI runs today.**
  - **A probe test can overrun on a loaded macOS runner**
    ([#1309](https://github.com/feedback-loop-ai/brokkr/issues/1309)).
    The probe evidence test re-runs itself in an engine of its own
    under a 180-second deadline, and a slow macOS runner can pass that
    deadline. It is the test's deadline: nothing seen points at
    `brokkr` itself.
  - **A dispatch test admitted nothing on a macOS runner**
    ([#1374](https://github.com/feedback-loop-ai/brokkr/issues/1374)).
    `dispatch::a_pass_hands_its_run_to_a_driver_of_its_own_that_completes_it`
    saw a dispatch pass that ran and claimed nothing. Its cause is not
    established. The suspect is decision 0125's macOS memory-pressure
    veto, under the runner's memory pressure. **On macOS, expect
    this:** decision 0125 runs decision 0068's count checks before the
    pressure veto, so an entry already blocked by an earlier check (for
    example at its provider ceiling) still shows that reason
    (`provider_full`); every entry that passes those checks waits as
    `memory_pressure` while the kernel reports memory pressure at warn
    or critical, and `brokkr queue list` names the level. If an entry
    does not start, read its reason there.
- **A bound value that an escape sequence both interrupts and partly
  consumes can stand partly in clear in stderr evidence**, as it does in
  0.15.2 ([#1242](https://github.com/feedback-loop-ai/brokkr/issues/1242)).
  The operator accepted this as a named residual, under decision 0012's
  transformed-shape exclusion, when the stderr evidence work landed.
  The issue stays open for decision 0114's remaining work.
- **The agy transcript keeper's stated limits**
  ([#1375](https://github.com/feedback-loop-ai/brokkr/issues/1375)).
  The operator ruled that a process of the operator's own user acting on
  `~/.local/state/brokkr/agy-conversations/` while a transcript is being
  kept is a stated limit, not defended against. The last two commits of
  that work landed by hand and were checked by the pull request's CI
  alone; their review is pending.
- **Kept session files are never removed:** dsh's kept homes and agy's
  kept transcripts have no reaper yet
  ([#1323](https://github.com/feedback-loop-ai/brokkr/issues/1323)).
- **The dsh hands fix's last commit was not judged by a lane run**
  ([#1378](https://github.com/feedback-loop-ai/brokkr/issues/1378)). It
  changes a test helper and the hands reference only.
- **Two flaky tests, seen only under heavy parallel load, are still
  open:** [#1157](https://github.com/feedback-loop-ai/brokkr/issues/1157)
  and [#1164](https://github.com/feedback-loop-ai/brokkr/issues/1164).
- The known issues listed in [v0.15.0](v0.15.0.md#known-issues) that
  this release does not address still apply.
