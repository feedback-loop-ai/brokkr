# v0.14.1: a park names its cause, `brokkr dispatch --once` starts queued runs under a run ceiling, Claude Code 2.1.326 decodes whole, and the harness probe binds a login file

v0.14.1 is a patch on
[v0.14.0 “Megingjörð”](v0.14.0.md). It carries the fixes that were in
flight when 0.14.0 shipped, and the changes merged beside them. It
includes everything merged since
[v0.14.0](https://github.com/feedback-loop-ai/brokkr/releases/tag/v0.14.0).

It needs no migration. Read
[Upgrade and compatibility](#upgrade-and-compatibility) if you use
`brokkr queue` or `brokkr dispatch`, or match an admission-lock refusal
by its text.

## What changed

- **A park names its cause, typed and closed (decision 0106, slice
  0106a; [#1116](https://github.com/feedback-loop-ai/brokkr/pull/1116)).**
  - **The cause.** Every `run/parked` event carries one of `ruled`,
    `infrastructure` (with `retryable`), `attempt-cap` (with its failure
    class) or `provider-limit` (with a typed refusal). Every writer builds
    its payload through one constructor that takes a cause.
  - **The contract.** The cause is recorded under the new frozen contract
    `park-cause/v1`. A park written before 0.14.1 has no cause, and the
    readouts leave it off the wire.
  - **Retryable.** A contention park is `retryable` only on the evidence
    decision 0106 ruling 4 names, read from what stands in the
    coordination root.
  - Nothing spends `retryable` yet. Slices 0106b to 0106e build the held
    wait, the lift and the budget on it.
- **`brokkr dispatch --once` starts what admission admits (decision 0110,
  slices 6a, 6b and 6d;
  [#1107](https://github.com/feedback-loop-ai/brokkr/pull/1107),
  [#1122](https://github.com/feedback-loop-ai/brokkr/pull/1122),
  [#1117](https://github.com/feedback-loop-ai/brokkr/pull/1117)).**
  - **One pass.** `brokkr dispatch --once` runs one pass under the
    journal's dispatch lock, and hands each run it starts to a driver of
    its own. The standing loop is not built yet, so `brokkr dispatch`
    without `--once` is refused.
  - **`brokkr dispatch set-bound <n> --reason <why>`** sets how many
    refusals one entry may meet before the dispatcher holds it, journaled
    as the operator's command.
  - **`brokkr dispatch status`** says whether a dispatcher holds the
    journal, the bound in force, and each entry left launching or linked
    with no `spawn` row. It opens the journal read-only.
  - **The run ceiling.** `forge.host/v4` requires `runs.ceiling` of at
    least 1, so one journal drives no more runs than its host declares.
    An entry at the ceiling waits as `runs_full`.
- **The harness probe decodes Claude Code 2.1.326
  ([#1128](https://github.com/feedback-loop-ai/brokkr/pull/1128)).**
  - Its new fields in the stdout stream, the transcript and the MCP log
    are each read or declared inert, so `brokkr probe harness` measures
    2.1.326 again.
  - A `tool_use` block in a request blob, or a `tools` key in request
    params, is still refused.
- **The harness probe binds a CLI's login file, `--credential-file`
  ([#1134](https://github.com/feedback-loop-ai/brokkr/pull/1134)).**
  - **The flag.** `brokkr probe harness --credential-file <path under
    HOME>` (repeatable, e.g. `.codex/auth.json`) names a login file. It
    must be a regular file of plain path names, mode 0600.
  - **How it is bound.** The file is linked at the same place under the
    scratch HOME for each credentialed launch, and unlinked after, so the
    launch without credentials still meets the auth refusal.
  - **A refresh is kept.** A CLI that writes the file in place writes
    through the link. One that renames a new file over the link has it
    copied back, 0600.
  - The report names the file as `~/<path>` beside the bound names. Its
    content is never read.
- **Decision 0109, accepted
  ([#1120](https://github.com/feedback-loop-ai/brokkr/pull/1120)).** A
  gate's re-visit reads what changed since its last verdict, plus the
  findings that still stand, unless a declared trigger asks for a whole
  read. Docs only; it is not built yet.

## Fixed

- **A cooling run's waits are painted once, from what core wrote
  ([#1111](https://github.com/feedback-loop-ai/brokkr/pull/1111)).**
  `runs`, `inspect`, the TUI, `compare` and the run pages read one home.
  A run whose fold refuses paints no wait.
- **A dsh seat's git works without signing
  ([#1123](https://github.com/feedback-loop-ai/brokkr/pull/1123),
  closes [#1109](https://github.com/feedback-loop-ai/brokkr/issues/1109)).**
  dsh's environment scrub dropped `GIT_CONFIG_KEY_0`, which broke every
  git command in the seat. Every seat now gets one
  `GIT_CONFIG_PARAMETERS` setting, `commit.gpgsign=false`, which the scrub
  keeps.
- **Settle's follow-ups close
  ([#1108](https://github.com/feedback-loop-ai/brokkr/pull/1108),
  [#1118](https://github.com/feedback-loop-ai/brokkr/pull/1118), closes
  [#1099](https://github.com/feedback-loop-ai/brokkr/issues/1099)).** A
  reseal refused with `Unsealed` no longer leaves its own successor
  standing as the record. Settle's last unbound clauses are tested, and
  the undo's docs state each arm.
- **The admission lock's refusal names its cause
  ([#1114](https://github.com/feedback-loop-ai/brokkr/pull/1114)).** The
  sentence now ends with the open's errno, or the clause of the
  single-file check that failed.
- **Analytics reads stay bounded (decision 0089 slice 4, #753;
  [#1104](https://github.com/feedback-loop-ai/brokkr/pull/1104),
  [#1115](https://github.com/feedback-loop-ai/brokkr/pull/1115)).** Every
  window statement leaves out the whole read's runs from one home. The
  parks statement is one indexed arm under the operator's cap, and a
  hearth's row read is one database snapshot.
- **Flaky tests that could drop a pull request from the merge queue:**
  - the cool-down probe and the dispatch deadline-words tests no longer
    depend on the host's load, and a failing one prints what each member
    did ([#1121](https://github.com/feedback-loop-ai/brokkr/pull/1121),
    [#1125](https://github.com/feedback-loop-ai/brokkr/pull/1125));
  - `heap_costs`' compare holds to the byte on a slow host
    ([#1131](https://github.com/feedback-loop-ai/brokkr/pull/1131)).
- **The flake's digests** match v0.14.0
  ([#1106](https://github.com/feedback-loop-ai/brokkr/pull/1106)).

## Upgrade and compatibility

- **Host files before `forge.host/v4`.** `brokkr run` is unaffected.
  Under a `forge.host/v1` to `v3` file, every measured entry of
  `brokkr queue` and `brokkr dispatch` waits as `runs_undeclared`, and
  `brokkr doctor` warns. Move the file to `forge.host/v4` and declare
  `runs.ceiling` to start queued runs.
- **The admission lock's refusal** keeps its sentence and appends
  `: <cause>`. A reader that matches the old sentence exactly must match
  its prefix instead.
- **Contracts.** `park-cause/v1` is new and additive; an event without a
  cause is read as before. The engine, event schema, database schema and
  driver protocol versions are otherwise unchanged.
- **Engine version.** Bundle digests cover the engine version, so a run
  started under 0.14.0 resumes only under 0.14.0's binary.

## Known issues

- **A provider's reset past the declared maximum still parks the run.**
  The park now names its cause as `provider-limit`. Decision 0106's held
  wait and lift remain the fix
  ([#1035](https://github.com/feedback-loop-ai/brokkr/issues/1035)).
- **`route_overlay_driver`'s tests still fail intermittently** on hosted
  macOS merge-group runners. The refusal now names its cause, so the next
  failure says why
  ([#1082](https://github.com/feedback-loop-ai/brokkr/issues/1082)).
- **Two cool-down sequence tests** can still fail under the host's load.
  They now print what each member did
  ([#1110](https://github.com/feedback-loop-ai/brokkr/issues/1110)).
- The known issues listed in [v0.14.0](v0.14.0.md#known-issues) that
  this release does not address still apply.
