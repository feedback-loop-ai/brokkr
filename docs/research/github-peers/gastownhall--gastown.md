## What actually runs

Gas Town is a Go workspace manager with an agent-assisted management layer. A **town** contains project **rigs**; persistent polecat identities have replaceable sessions and Git worktrees, while crew members have longer-lived workspaces. The Mayor interprets requests; Witness and Deacon supervise workers; the Refinery processes merge requests. Beads stores task/hook/molecule state in a town-level Dolt SQL server. Tmux, Git, process registries, daemon files, and an event feed supply additional state. This is operationally richer than “a Mayor tells coding agents what to do,” but the combined state is not a single append-only journal or pure fold. [Architecture](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/docs/design/architecture.md), [README](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/README.md).

The source module requires **Go 1.26.2** and the Beads library `v1.0.5`; the README separately requires Beads CLI `0.57+`, Git, tmux, sqlite3, and a running Dolt server, with ICU development libraries for source builds. These CLI/library versions are distinct. The inspected architecture explicitly rejects an embedded database fallback. Supported-agent configuration includes Claude, Codex, OpenCode and other CLIs, but agent availability does not imply identical lifecycle or permission guarantees. [Module](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/go.mod), [agent presets](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/config/agents.go).

```text
formula TOML + overlays → parse/resolve dependencies → sling admission + locks
    → provision worker / instantiate molecule → durable hook → start tmux agent
    → agent acknowledges completed step → bd ready --mol → next runnable steps
    → submit merge request → Refinery gates + source/base checks → external merge
```

## Graphs, roles, and reusable policy

Formulas are typed as workflow, convoy, expansion, or aspect. Steps have IDs, dependency lists, descriptions, acceptance text, and parallel/interactive flags. Parsing checks duplicate IDs, missing dependencies, and cycles; resolution follows inheritance and expansions. `compose.aspects` is explicitly reserved for future implementation. A formula defaults to a root-only representation unless `pour` requests materialized step checkpoints. Do not equate an acceptance string with executable verification. [Types](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/formula/types.go), [parser/resolver](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/formula/parser.go).

Graph progression is real: `gt mol step done` closes the step, invokes canonical `bd ready --mol`, and distinguishes remaining runnable steps, blocked work, and completed molecules. The acknowledgement originates from the worker command; this path does not independently prove the step’s semantic acceptance. [Step progression](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/cmd/molecule_step.go).

Role prompts, formula bodies, runtime presets, hooks, and overlays together approximate reusable agents/charters. Rig overlays override town overlays; they can replace, append, or **skip** steps, rewiring dependencies through skipped nodes. Consequently, a review step is configurable workflow content rather than a protected invariant comparable to Brokkr’s policy review. Formula provisioning records hashes and preserves user-modified definitions, which supports upgrades but does not freeze a run’s entire policy dependency closure. The formula-tier design document labels its broader resolution/federation proposal “Partially implemented.” [Overlays](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/formula/overlay.go), [provisioning](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/formula/embed.go), [design status](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/docs/design/formula-resolution.md).

## Dispatch refusal and partial-effect recovery

The common batch/queue dispatch path acquires per-bead locks, rejects parked/docked rigs, refuses closed/tombstoned tasks even with force, and distinguishes deferred tasks from stale ownership. Same-target reuse is deliberately restricted to unambiguous agent identifiers; ambiguous shorthand and pool targets cannot silently reuse a possibly different worker. Deferred scheduling persists launch context and fails on database errors while checking existing context. Default nonpositive `max_polecats` means immediate dispatch rather than capacity-limited queuing. [Dispatch](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/cmd/sling_dispatch.go), [idempotency](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/cmd/sling_idempotency.go), [scheduler](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/cmd/sling_schedule.go).

Dispatch spans worker creation, convoy creation, formula instantiation, hook mutation, event emission, branch setup, and session startup. The source contains rollback/cleanup branches, but these effects are not one atomic transaction. Formula failure is also context-dependent: the dispatcher documents fatal cleanup for single/queued work, versus a batch option that falls back to hooking the raw bead. The common implementation covers batch and queued paths; single sling retains separate implementation, so uniformity should not be assumed. Formula launch checks textual output because an external `bd` command can report a missing formula while exiting zero. [Dispatch parameters](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/cmd/sling_dispatch.go), [formula launch/cleanup](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/cmd/sling_formula.go).

This is valuable evidence for explicit refusal and compensation design, not an exactly-once guarantee for external operations. Source-specific deduplication is narrower and more credible than a blanket “resumable agent” claim.

## Process lifecycle, bounds, and permissions

Session startup centralizes role/workdir validation, agent settings, environment construction before tmux creation, optional readiness/survival checks, PID tracking, and run IDs. Readiness failure is fatal only when the corresponding option requests it. Default Claude and Codex presets include permission-bypass flags; OpenCode’s preset similarly grants broad permissions. Git worktrees isolate edits structurally, not hostile code or secrets. [Lifecycle](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/session/lifecycle.go), [presets](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/config/agents.go).

Tmux teardown disarms respawn, snapshots descendants, adds matching process-group members, sends TERM and then KILL, and kills the session. In this particular path, descendant signals use captured numeric PIDs without revalidating process birth identity before every signal. A separate shutdown PID-tracking fallback **does** compare recorded start times when available; legacy entries may lack them, and its successful TERM path removes the tracking record without proving process exit. These are separate mechanisms and should not be summarized as universal identity-safe cancellation. [Tmux teardown](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/tmux/tmux.go), [PID tracking](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/session/pidtrack.go).

The daemon has restart backoff, crash-loop quarantine, stable-run reset, and a special quota pause that avoids consuming the crash budget. State is persisted separately in `restart_state.json`. Refinery gate timeouts use `exec.CommandContext`, but the inspected production gate path calls **`SetDetachedProcessGroup`**, whose Unix implementation deliberately installs no group cancellation hook. Thus this path does not establish descendant termination when a timed-out shell spawned children. Gate stdout/stderr accumulate in buffers before error text is truncated; the displayed limit is not a capture bound. These are source-derived limitations, not reproduced failures. [Restart tracker](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/daemon/restart_tracker.go), [gate execution](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/refinery/engineer.go), [process helpers](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/util/exec_unix.go).

## Merge effects, evidence, and verification

The Refinery includes concrete defenses: submitted/source SHA checks, base-sensitive preverification, configurable premerge/postsquash gates, and fresh task/flag/source checks immediately before push or PR merge. A matching-base `PreVerified` request can skip gate execution; this is a trust shortcut, not mandatory independent rerunning. A persistent `safety_stop:*` label blocks refinery startup until cleared. [Engineer](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/refinery/engineer.go), [safety stop](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/refinery/safety_stop.go), [prepush tests](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/refinery/prepush_recheck_test.go).

The event feed is flock-protected JSONL without a hash chain or fsync in its writer. A separate detach audit writer fsyncs, but audit failure warns while detach can proceed. Durable operational records therefore do not establish Brokkr-style atomic, tamper-evident transition evidence. [Event writer](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/events/events.go), [detach audit](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/beads/audit.go).

Tests cover formula dependency/cycle/overlay behavior, formula provisioning, PID reuse, per-bead dispatch locking, cleanup after formula failure, and changes discovered during prepush rechecks. CI builds on Ubuntu, runs short race-enabled Go tests, and includes integration scenarios with real Beads/Dolt infrastructure. Windows-specific source exists, but this CI does not qualify every runtime/OS combination. These are inspected test definitions, not fresh test results. [Formula tests](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/formula/parser_test.go), [overlay tests](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/formula/overlay_test.go), [PID tests](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/session/pidtrack_test.go), [dispatch lock tests](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/cmd/sling_dispatch_lock_test.go), [cleanup tests](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/cmd/sling_formula_cleanup_test.go), [CI](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/.github/workflows/ci.yml).

## Lessons and bounded Brokkr experiments

Gas Town supplies stronger concrete graph scheduling, worker supervision, and merge reconciliation than a prompt-only swarm. Brokkr supplies a smaller deterministic outer protocol with stronger intended policy/evidence centralization; neither architecture subsumes the other.

1. Prototype dependency-ready task selection **inside** a bounded Brokkr phase, retaining protected outer review and explicit maximum concurrency.
2. Port the idea of per-task admission locks and fresh source/authorization checks immediately before effects into dispatcher and retry qualification (#430/#434).
3. Test cancellation with descendants that outlive their shell, PID reuse, partial startup, and delayed cleanup (#403/#433); distinguish process snapshots from identity validation.
4. Require explicit provenance for preverified work and persist uncertain push/merge outcomes before reconciliation. Test phase recovery across the multiple stores without assuming a clean restart equals replay.

The linked production files and corresponding [source manifest](source-manifest.json) form the evidence ledger. Open questions include deployment-specific agent confinement, crash consistency across Dolt/Git/tmux, and external-effect reconciliation under network partitions; this inspection does not claim those have been experimentally qualified.
