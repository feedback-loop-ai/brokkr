## Architecture and graph semantics

```text
Markdown + frontmatter + imports → Go validation/compiler → reviewed .lock.yml
    → pre-activation authorization/stop checks → activation + lock check
    → sandboxed agent emits proposed outputs → collector/sanitizer + detection
    → privileged safe-output handlers → external APIs + outcome artifacts
```

The outer graph is an actual **GitHub Actions jobs/dependencies graph**, with custom jobs and reusable/called/dispatched workflows. Engine-native reasoning and subagent scheduling occur inside the agent job. Inline named agents are extracted into engine-specific agent directories and restored from activation artifacts; defining one does not prove that its parent actually invokes it. Thus this combines deterministic stage ordering with an agent-interpreted interior, resembling Brokkr’s separation of outer control and inner panels more than a universal agent DAG. [Pre-activation builder](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/pkg/workflow/compiler_pre_activation_job.go), [safe-output job conditions](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/pkg/workflow/compiler_safe_outputs_job.go), [subagent restoration](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/pkg/workflow/sub_agent_step.go).

Imports compose prompts, tools, MCP servers, and configuration. Their merge rules deserve review: tools combine allowed arrays, while the inspected MCP merge assigns imported server definitions over same-named top-level definitions. Reuse can therefore change capabilities. Roles/charters are distributed across Markdown, imported content, engine-native agent files, and typed configuration; there is no single mandatory charter contract equivalent to Brokkr’s pinned agent manifest. [Import merging](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/pkg/workflow/imports.go), [inline agent semantics](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/docs/src/content/docs/reference/inline-sub-agents.md).

## Compilation, provenance, and refusal

Strict mode defaults on, with repository/CLI enforcement taking precedence over a workflow’s setting. Safe-update checks share that policy but can be explicitly approved through `--approve`. The compiler compares new secrets, action references, redirect changes, memory-validation scripts, and specified trigger escalation against the prior manifest, preferentially read from committed HEAD. Newly introduced workflows get an empty baseline; legacy lockfiles without a manifest skip that comparison. Infrastructure secrets and selected trusted actions receive exceptions. This is concrete capability-change review, not a complete immutable dependency lock. [Policy resolution](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/pkg/workflow/compiler_yaml_policy.go), [compilation/baseline path](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/pkg/workflow/compiler.go), [safe updates](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/pkg/workflow/safe_update_enforcement.go).

Runtime activation refuses a frontmatter hash mismatch or an unverifiable lock, with a separate diagnostic for cross-repository authorization failure. **Body comparison requires `on.stale-check: full`;** older locks without a body hash skip it. The compiler also supports disabling the stale-check step. Therefore “the lock pins all prompt behavior” overstates the default. Go and JavaScript hash implementations have cross-language consistency tests. [Runtime check](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/actions/setup/js/check_workflow_timestamp_api.cjs), [step generation](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/pkg/workflow/compiler_activation_steps.go), [hash tests](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/pkg/parser/frontmatter_hash_cross_language_test.go).

Validation is layered. Agent-job write permissions are rejected across scopes except OIDC/metadata; custom jobs and safe-output jobs deliberately lie outside that validator. Strict validation rejects a disabled agent sandbox and arbitrary top-level/engine environment secret exposure, with recognized engine authentication exceptions. Custom step `env`/Action `with` secret bindings remain supported. Template-expression injection validation is distinct from optional validation of the generated Actions YAML schema; the compiler constructor defaults the latter off, and CLI configuration controls it. Do not collapse these into “all validation disabled” or “every scanner mandatory.” [Permission validation](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/pkg/workflow/dangerous_permissions_validation.go), [sandbox rules](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/pkg/workflow/strict_mode_sandbox_validation.go), [environment rules](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/pkg/workflow/strict_mode_env_validation.go), [step secrets](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/pkg/workflow/strict_mode_steps_validation.go), [compiler defaults](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/pkg/workflow/compiler_options.go).

## Isolation, secrets, and controlled effects

The runtime profiles make the distinction explicit: default Docker uses rootless AWF and isolated networking; `docker-sudo-iptables` enables a more privileged legacy profile; Cloud Hypervisor is a separate preview microVM profile. The architecture documents Linux hosted/self-hosted runners and an ARC Docker-in-Docker topology, with host/kernel/container/network infrastructure inside the trust boundary. This source configures external AWF/MCP components; their complete isolation implementation was outside this repository inspection. Read-only GitHub permissions alone do not constrain credentials deliberately supplied through custom jobs or integrations. [Runtime profiles](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/pkg/workflow/sandbox_runtime_profile.go), [architecture and topology limits](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/docs/src/content/docs/introduction/architecture.mdx).

Safe outputs are real deferred operations. The agent emits proposed messages; collection validates configured types, field schemas, counts, repository targets, and sanitizes content before handlers receive artifacts. Separate jobs compute permissions and can mint scoped App tokens. A staged mode reports previews without performing handler writes. Bounds are configurable: `max: -1` explicitly means unlimited, so mere presence of the subsystem is not a finite effect budget. [Collector](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/actions/setup/js/collect_ndjson_output.cjs), [job scaffolding](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/pkg/workflow/safe_outputs_jobs.go), [max validation](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/pkg/workflow/safe_outputs_max_validation.go).

Detection is enabled by default for configured safe outputs, but **`continue-on-error` defaults true**. Runtime warning policy allows outputs categorized as reviewable, converts branch pushes into proposed PRs, and aborts listed mutations such as merge/close/dispatch. Unclassified custom/extension handler types are explicitly allowed with a warning for compatibility. Conditional detection may be skipped by its configured expression. Thus the architecture diagram’s “approved then write” should not be read as mandatory blocking review of every output. [Detection configuration](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/pkg/workflow/threat_detection_config.go), [warning policy and dispatcher](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/actions/setup/js/safe_output_handler_manager.cjs).

## Lifecycle, retries, resume, and uncertain effects

Default budgets distinguish **20-minute engine step**, **60-minute agent job**, and **10-minute detection job**; explicit values may extend them. AWF startup retries default to one and clamp at two, requiring a recognized startup error before the harness marker. Once the marker appears, this wrapper will not blindly rerun the engine. The marker is the implementation’s evidence boundary, not a demonstrated guarantee under every logging failure. MCP shutdown attempts an authenticated close, bounded waits, TERM/KILL, and an EXIT trap stopping/removing its named container. Complete workload cancellation also depends on Actions and the external runtime; the helper uses numeric PID checks rather than general process birth-identity verification. [Budgets](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/pkg/constants/constants.go), [job resolution](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/pkg/workflow/job_timeouts.go), [startup retry wrapper](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/actions/setup/sh/run_awf_with_startup_retries.sh), [MCP shutdown](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/actions/setup/sh/stop_mcp_gateway.sh).

External writes require separate scrutiny. `create_issue` wraps the API call in a retry policy that includes network timeouts, resets, and transient HTTP statuses. Optional title deduplication is disabled by default and is a search-based heuristic, not a transaction identity. The handler manager logs success **after** the handler returns; manifests are ordinary appended JSONL, redacted recursively before serialization. A successful remote mutation followed by a lost response, process interruption, or manifest failure is not resolved by an atomic local/remote commit protocol in these paths. This is a source-derived uncertain-effect limitation, not a reproduced duplicate-issue bug. [Issue handler](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/actions/setup/js/create_issue.cjs), [retry classification](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/actions/setup/js/error_recovery.cjs), [dedup defaults](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/actions/setup/js/issue_title_dedup.cjs), [manifest writer](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/actions/setup/js/safe_output_manifest.cjs).

Safe-output dispatch supports temporary-ID dependency ordering, deferred references, per-message failure reporting, and subsequent summaries; partial successes can remain externally visible. Cache memory persists selected files across Actions runs and supports validation, but is not a checkpoint of an interrupted agent process or a replayable event fold. No general effect-level resume/exactly-once guarantee was established. [Handler manager](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/actions/setup/js/safe_output_handler_manager.cjs), [memory contract](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/docs/src/content/docs/reference/cache-memory.md).

## Tests, maintenance, and Brokkr lessons

The test surface is substantial: Go compiler/unit/integration tests, JavaScript Vitest suites, shell startup-retry tests, fuzz targets, generated-workflow checks, and live-API CI variants. Tests named “formal” map specification predicates to Go assertions—for example, rejecting write scopes, default continue-on-error, and job topology. These inspected tests do not themselves prove a hostile runtime cannot escape its substrate. [Security predicate tests](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/pkg/workflow/security_architecture_sg_formal_test.go), [safe-output tests](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/actions/setup/js/safe_output_handler_manager.test.cjs), [retry shell tests](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/actions/setup/sh/run_awf_with_startup_retries_test.sh), [CI](https://github.com/github/gh-aw/blob/4d1d3ec71b568eb37974720f334c45914da0b95b/.github/workflows/ci.yml).

The strongest transferable design is the **separate, typed, least-privilege effects stage**, coupled with inspectable compiled artifacts and capability-change checks. Brokkr can test this without replacing its linear outer machine:

1. Compile recipes/charters into a reviewable capability manifest and refuse unapproved changes on restore (#429/#431/#432).
2. Buffer proposed effects, validate types/targets/counts, and execute with narrowly scoped credentials after protected review (#430).
3. Qualify startup-only retry separately from inference/effect retry; inject a lost API response after successful mutation and reconcile before repeating (#434).
4. Make review disposition and unknown-output policy explicit; require finite bounds and test every refusal through the production dispatcher (#433/#435–439).

The exact-revision links plus [source manifest](source-manifest.json) are the evidence ledger. Open boundaries are external AWF/Gateway behavior, engine-specific cancellation, and live service consistency under failure; none were experimentally qualified here.
